Где части 0–14 и проработка 01.07 расходятся, приоритет у частей 0–14 (они новее). Расхождения
фиксировать в плане как вопросы, а не выбирать молча. Известные расхождения:
- 01.07: параметр «Создать вебинар в МТС Линк» в карточке обычного очного мероприятия;
  части 0–1: отдельный тип мероприятия «МТС Линк», тип не меняется после создания.
- 01.07: проверка менеджера в организации МТС Линк перед созданием, вебинар под его учёткой;
  части 0.1/1: интеграция на уровне тенанта по токену, создание фоном с ретраями.
- 01.07: автозапуск за 10 минут, запись 720p/view=questions, хранение записи 3 месяца, зачёт часов
  пропорционально времени + просмотр записи; части 9/11: порог 75 %, зачёт по записи только если
  очно не засчитано. Часть 11 не описывает пропорцию часов — вопрос.
- Часть 9 требует «фактическую длительность вебинара из данных МТС»; откуда она берётся, не описано.

## p2p/ — практическое задание: режим взаимопроверки peer-to-peer

| Файл | Что это | Актуальность |
|---|---|---|
| 01_черновик_v1 | первое понимание + вопросы Максиму | устарел |
| 02_промежуточная_версия_и_сверка_с_ТЗ | версия с параметром «Доступно для взаимопроверки» в карточке ПЗ и всеми настройками в потоке; во второй половине — сверка с исходным ТЗ (что из ТЗ, что наше решение) | частично устарел; **сверка с ТЗ — обязательна к учёту**: исходное ТЗ требует новый тип «ПЗ ВЗАИМОПРОВЕРКА», лимиты N проверок, уникальные ссылки на каждый ответ, каждый преподаватель проверяет один раз |
| 03_проработка_полная_с_комментариями_Максима | полная проработка: роли, настройки в карточке и в потоке, типы критериев (шкала с весами, ОиМ/МиМ с гистограммами, текст), статусная модель работы и проверки, отчёт PDF/Word, сертификаты, смета | **актуальная детальная модель** (статусы, критерии, отчёт) |
| 04_версия_после_встречи_с_заказчиком | итог встречи с заказчиком: что уточнено, что под вопросом; штатные проверяющие ПЗ, слушатель-проверяющий, внешний по ссылке видит список всех работ | **самая свежая согласованная версия — приоритет** |
| 05_вопросы_заказчику_16 | 16 вопросов заказчику с предлагаемыми вариантами | открытые вопросы; каждая проверка по ним помечается «ждёт ответа заказчика» |

Приоритет при расхождениях: 04 → 03 → 02. Известные расхождения:
- право итогового результата: 04 — любой штатный проверяющий ПЗ; 03 — отдельный признак
  «Может выставлять итоговый результат»; 02 — верификация преподавателем.
- внешний проверяющий: 04 — видит список всех сданных работ ПЗ в потоке, ссылка многоразовая;
  03/05 — видит только одну работу, ссылка одноразовая на пару «работа — проверяющий».
- где настройки: 04 — критерии и штатные проверяющие в карточке ПЗ, распределение в потоке;
  02 — в карточке только флаг, всё остальное в потоке.
- возврат на доработку: 04 — штатный проверяющий, повторный цикл; 03 — настройка «разрешить
  возврат», приостановка у всех; 01 — на первом этапе не использовать.
- итог без штатных проверяющих (авто-среднее по «Общей оценке») — вопрос заказчику.
