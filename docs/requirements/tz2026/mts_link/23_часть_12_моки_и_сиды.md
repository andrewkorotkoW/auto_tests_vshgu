Часть 12. Моки и сиды для интеграции с МТС Линк
Задача
Обеспечить возможность разрабатывать и проверять интеграцию с МТС Линк без обращения к реальному внешнему сервису.
Зачем
Интеграция завязана на внешнюю систему: нужен валидный токен, живой аккаунт, реальные вебинары. Разработчик не может каждый раз создавать вебинары в боевом аккаунте, а часть сценариев — ошибка авторизации, недоступность сервиса, отказ при загрузке файла — в реальной системе воспроизвести трудно.
Моки клиента МТС Линк
Заглушка вместо реального обращения к МТС Линк, возвращающая предсказуемые ответы по всем используемым операциям:

* проверка доступа (валидация токена);
* создание сессии и вебинара;
* обновление данных вебинара;
* регистрация и удаление участников;
* назначение и снятие лекторов;
* загрузка файла в хранилище и привязка к вебинару;
* удаление вебинара и сессии;
* получение статистики посещения;
* получение записи вебинара.

Мок отдаёт не только успешные ответы, но и ошибки: авторизации, недоступности сервиса, отказа по конкретному объекту. Без этого не проверить статусы, уведомления и ручной перезапуск.
Переключение между реальным клиентом и моком — через конфигурацию окружения.
Сиды
Готовые тестовые данные для локальной разработки:

* тенант с настроенной и проверенной интеграцией;
* тенант без интеграции (для проверки, что тип мероприятия скрыт);
* мероприятие типа «МТС Линк» с потоком слушателей, преподавателями и файлами презентаций;
* мероприятия в разных состояниях интеграции: успешно, в процессе, ошибка;
* статистика посещения с разными процентами — выше порога, ниже порога, нулевая, отсутствующая.

Цель — поднять окружение и сразу увидеть все состояния интерфейса, не собирая данные руками.
Результат
Интеграция разрабатывается локально без реального аккаунта МТС Линк, все состояния интерфейса и ошибочные сценарии воспроизводятся управляемо.
