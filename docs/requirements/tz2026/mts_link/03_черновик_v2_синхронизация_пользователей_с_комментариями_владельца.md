Синхронизация пользователей
АСУО является мастер-системой по пользователям, участвующим в вебинарах. Данные пользователей передаются из АСУО в МТС Линк через API. 

Пользователи:
Корпоративные пользователи ranepa.ru
Нужно синхронизировать с уже существующими корпоративными учетными записями МТС Линк.
Иные пользователи
Их нужно создать или синхронизировать в МТС Линк, если они нужны для участия в вебинаре.
Если Email ранее регистрировался, то новые данные будут проигнорированы. Использоваться будут существующие данные.

Процесс синхронизации:
АСУО выполняет поиск пользователя в МТС Линк через API.
 В API есть метод “Найти контакт”:
Исходя из ТЗ основное поле сопоставления - email, потому что в ТЗ отдельно указана корпоративная почта ranepa.ru.
В апи есть методы поиска:  по email, имени, фамилии, компании, телефону, должности, тегам или ID контакта.
Если пользователь найден, АСУО сохраняет связь.
API возвращает contactID, userId.  АСУО может сохранить у себя связь: пользователь АСУО - contactID / userId МТС Линк.
Если пользователь не найден, АСУО создает контакт в МТС Линк.
В API есть метод “Создать контакт”. Обязательное поле - email;
также можно передать имя, фамилию, компанию, должность, телефон, теги. Email указан как уникальный идентификатор контакта.
АСУО может обновлять данные контакта.
В API есть метод “Обновить контакт”. Можно обновить email, имя, фамилию, компанию, должность, телефон.
Для менеджеров организации отдельная логика:
В API есть метод получения сотрудников организации. По нему можно фильтровать сотрудников по id, роли, email, должности. Возвращаются UserID, роль, ФИО, email, телефон, должность, организация.
Также есть метод «Добавить сотрудников в организацию», но это именно отправка приглашения сотруднику; после этого сотрудник должен подтвердить добавление в личном кабинете. Обязательные поля: email, имя, фамилия, телефон, роль.

Если Email ранее регистрировался, то новые данные будут проигнорированы. Использоваться будут существующие данные.


Менеджер (сотрудник организации)
По ТЗ вебинар должен создаваться в МТС Линк под учетной записью менеджера, который создал очное мероприятие в АСУО. Пользователь синхронизируется после создания очного мероприятия в АСУО.

если менеджер уже есть в МТС Линк как сотрудник организации - вебинар создается сразу;
если менеджера нет - АСУО должен инициировать добавление/приглашение, пока менеджер не подтвержден/не появился как сотрудник организации, создание вебинара под его учеткой может быть недоступно.


Важный момент по API: До подтверждения приглашения менеджером создание вебинара под его учетной записью может быть недоступно. Если менеджера нет среди сотрудников организации МТС Линк, АСУО может через API отправить ему приглашение в организацию.

Процесс:
Менеджер создает в АСУО очное мероприятие типа «Вебинар».
АСУО проверяет, есть ли менеджер в МТС Линк.
Если менеджера нет - АСУО создает/синхронизирует его в МТС Линк.
После этого АСУО создает вебинар в МТС Линк под учетной записью менеджера.

Это, скорее всего, сотрудники/корпоративные пользователи РАНХиГС: менеджеры, преподаватели, администраторы.
Их надо сопоставлять с корпоративными учетными записями МТС Линк.
Практически это значит:
АСУО берет пользователя с email ranepa.ru.
Через API проверяет, есть ли такой пользователь среди сотрудников организации МТС Линк.
Если найден — сохраняет связь: пользователь АСУО ↔ сотрудник МТС Линк.
Если не найден — АСУО может инициировать приглашение в организацию МТС Линк.

Слушатели (участник)
2. Регистрация на конкретный вебинар
Чтобы слушатель увидел/открыл конкретный вебинар, АСУО должна отдельно зарегистрировать его на это мероприятие в МТС Линк.
Это может происходить:
заранее — при назначении слушателя на вебинар в АСУО;
либо в момент перехода к конкретному вебинару.

Я бы выбрал синхронизацию после создания вебинара в МТС Линк, когда уже есть конкретный вебинар и понятен состав потока.
У МТС Линк в API есть отдельные методы регистрации участников на мероприятие, в том числе «Зарегистрировать на мероприятие списком», а также методы работы с контактами и сотрудниками организации.
Процесс:
АСУО создает вебинар в МТС Линк.
АСУО получает ID вебинара и ссылку.
При назначении слушателя на вебинар АСУО синхронизирует пользователя с МТС Линк.
После синхронизации АСУО регистрирует слушателя на конкретный вебинар в МТС Линк.
Слушатель видит вебинар в АСУО и переходит в него по ссылке.

Почему лучше не делать синхронизацию слушателя только в момент перехода
Так можно, но это рискованнее:
если API или авторизация даст ошибку, слушатель не попадет в вебинар прямо перед началом;
сложнее отлаживать;
сложнее гарантировать, что все слушатели зарегистрированы;
раз в API есть пачечная регистрация, логичнее регистрировать участников заранее.

Короткая формулировка для ТЗ
Синхронизация пользователей с МТС Линк выполняется по ролям. Учетная запись менеджера, создавшего очное мероприятие, должна быть синхронизирована до создания вебинара в МТС Линк, так как вебинар создается под его учетной записью. После создания вебинара в МТС Линк АСУО должна синхронизировать слушателей потока и зарегистрировать их на соответствующий вебинар списком. После регистрации слушатели получают возможность перехода из АСУО в вебинар МТС Линк.

Авторизация слушателя
После назначения слушателя на вебинар в АСУО и его регистрации на вебинар в МТС Линк возможны следующие способы доступа:

Переход из карточки очного мероприятия в АСУО. В карточке очного мероприятия типа «Вебинар» отображается кнопка/ссылка перехода в конкретный вебинар МТС Линк. Переход должен выполняться бесшовно, без повторного ввода логина и пароля, если пользователь уже авторизован в АСУО.
Переход из индивидуального расписания слушателя в АСУО. В индивидуальном расписании слушателя отображается вебинар с кнопкой перехода в мероприятие МТС Линк. Переход также должен выполняться бесшовно.  
Переход по кнопке в портал МТС Линк из АСУО. В АСУО должна быть предусмотрена кнопка перехода в корпоративный портал МТС Линк. Переход должен выполняться бесшовно, без повторной авторизации пользователя.
Не было в тз но можно, добавить функциональность: Переход по письму от МТС Линк. При регистрации слушателя на вебинар АСУО может разрешить МТС Линк отправить письмо с приглашением/ссылкой на вебинар. В этом случае слушатель может попасть в вебинар из письма, без перехода через АСУО.


Прохождение 
АСУО создает или синхронизирует слушателя в МТС Линк.
АСУО регистрирует слушателя на конкретный вебинар.
При переходе из АСУО пользователь попадает в МТС Линк через согласованный механизм авторизации/идентификации.
Слушатель не вводит пароль от МТС Линк вручную.


Запись вебинара
Предполагаемый процесс работы с записью вебинара:

Если при создании вебинара в АСУО включен параметр «Предоставить слушателям запись вебинара», АСУО создает вебинар(через API) в МТС Линк с включенной записью.
Вебинар проводится на стороне МТС Линк.
После завершения вебинара МТС Линк формирует запись вебинара.
АСУО через API инициирует подготовку/конвертацию записи 
либо проверяет статус подготовки записи
Пока запись не готова, АСУО может отображать в карточке мероприятия статус «запись готовится».
После готовности записи возможны два варианта:

Вариант 1. Хранение ссылки на запись
 АСУО получает из МТС Линк ссылку на просмотр записи и сохраняет ее в карточке очного мероприятия. Слушатели переходят к записи из АСУО по ссылке.
Вариант 2. Хранение файла записи в АСУО
 АСУО получает из МТС Линк сконвертированную запись или данные для ее скачивания, загружает файл в свое хранилище и отображает слушателям запись уже из АСУО.

В рамках доработки АСУО реализуется интеграция с платформой МТС Линк для проведения мероприятий типа “Вебинар”. АСУО является мастер-системой для создания учебного мероприятия, назначения слушателей, хранения связи вебинара с потоком и учета результатов обучения. МТС Линк используется как внешняя платформа для проведения вебинара, записи трансляции и фиксации факта участия слушателей.
При создании в АСУО очного мероприятия типа “Вебинар” пользователь с соответствующими правами может включить создание вебинара в МТС Линк. После сохранения мероприятия АСУО через API создаёт вебинар в МТС Линк, передаёт название, дату, время начала, продолжительность и часовой пояс, получает ссылку на вебинар и сохраняет её в карточке мероприятия.
При изменении или удалении мероприятия в АСУО соответствующие изменения должны быть синхронизированы с вебинаром в МТС Линк. После завершения вебинара АСУО получает из МТС Линк данные о записи и посещаемости. На основании полученных данных в АСУО проставляются отметки посещения слушателей, сохраняется источник отметки “МТС Линк”, а при наличии настройки в дисциплине посещение учитывается в “Результатах деятельности”.
Детализация физического хранения записи вебинара, правил определения посещения и сценариев синхронизации пользователей требует отдельного согласования с заказчиком.
