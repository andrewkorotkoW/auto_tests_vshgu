Интеграцию АСУО с внешней платформой МТС Линк.
Кратко: интеграция связывает вебинары АСУО с МТС Линк: вебинар создается в АСУО как очное мероприятие, проводится на платформе МТС Линк, а данные об участии слушателей передаются обратно в АСУО для фиксации посещаемости.

Что делаем:

1. Создание вебинара в МТС Линк из карточки очного мероприятия в АСУО;
2. Регистрация слушателями из АСУО вебинара МТС Линк;
3. Прохождение  слушателями из АСУО вебинара МТС Линк;
4. Получение из МТС Линк данных о посещении вебинара и времени нахождения слушателей;
5. Получение и отображение записи вебинара, если включен параметр предоставления записи;
6. Учет посещения вебинара в «Результатах деятельности»;
7. Синхронизация менеджеров/админов АСУО с МТС Линк;
8. Бесшовная авторизация пользователей админки (менеджеров)  между АСУО и МТС Линк;
9. Логирование действий интеграции.

Вроде правильная ссылка на апи МТС Линк: https://help.mts-link.ru/article/19615 
Создание вебинара
Вебинар создается в АСУО с помощью api МТС, как очное мероприятие типа «Вебинар». Если в карточке мероприятия включен параметр «Создать вебинар в МТС Линк», АСУО через API создает связанный вебинар на стороне МТС Линк.:

* Вебинар в МТС Линк создается под учетной записью менеджера, который создал очное мероприятие в АСУО.
   * Перед созданием вебинара АСУО проверяет менеджера среди сотрудников организации МТС Линк. Если менеджер найден, вебинар создается под его учетной записью. Если не найден - АСУО инициирует добавление/приглашение менеджера в организацию МТС Линк, но до подтверждения приглашения создание вебинара под его учетной записью может быть недоступно.


Что добавляется / используется в карточке очного мероприятия “Вебинар”:

1. Параметр «Создать вебинар в МТС Линк»
 При включении этого параметра АСУО после сохранения мероприятия создает вебинар в МТС Линк.
2. Параметр «Предоставить слушателям запись вебинара»
 Если включен, АСУО создает вебинар в МТС Линк с включенной записью.
3. Ссылка на вебинар
После создания вебинара МТС Линк возвращает ссылку, АСУО сохраняет ее в карточке очного мероприятия. (в админке нужно? или тут имеется ввиду только внешка)


Какие данные передаются в МТС Линк
АСУО передает через API:

1. название вебинара;
2. дату проведения;
3. время начала;
4. продолжительность;
5. часовой пояс тенанта (Часовой пояс вебинара;
6. данные менеджера/преподавателя вебинара;
7. настройку записи, если включен параметр предоставления записи.

При назначении слушателя на очное мероприятие типа «Вебинар» АСУО регистрирует этого слушателя как участника соответствующего вебинара в МТС Линк.
Регистрация слушателя из АСУО вебинара МТС Линк
Слушатель АСУО → участник конкретного вебинара МТС Линк
Слушатель - это участник вебинара. Его не нужно добавлять в организацию МТС Линк как сотрудника. Для него используется регистрация на конкретное мероприятие с ролью GUEST, которая является ролью по умолчанию в API регистрации. После регистрации МТС Линк возвращает уникальную ссылку входа в вебинар. 
Логика:

1. АСУО регистрирует слушателя сразу на конкретный вебинар через метод «Зарегистрировать на мероприятие».
2. В запросе передает минимум email, дополнительно можн - имя, фамилию, роль GUEST, параметры автовхода и отправки письма.
3. Если email уже раньше регистрировался на мероприятия организации, МТС Линк использует существующие данные и новые данные игнорирует.
4. Если email новый, МТС Линк создает контакт в разделе “Люди” и в ответе возвращает contactId и participationId
5. АСУО хранит ID мероприятия МТС Линк и ID участия слушателя, чтобы после вебинара получить статистику посещения и корректно проставить данные конкретным слушателям в АСУО.

Прохождение вебинара слушателем в АСУО
После назначения слушателя на очное мероприятие типа «Вебинар» АСУО регистрирует его как участника соответствующего вебинара в МТС Линк.

На внешке у  слушателя вебинар должен отображаться как учебное мероприятие в составе программы/расписания. Слушателю должны быть доступны основные сведения о вебинаре:

* название вебинара;
* дата и время проведения;
* преподаватель/ведущий, если указан;
* кнопка перехода в вебинар;
* после завершения вебинара - ссылка на запись, если для мероприятия включено предоставление записи.


При нажатии на кнопку  перехода очном мероприятии АСУО направляет слушателя в соответствующий вебинар МТС Линк. 

После завершения вебинара АСУО получает из МТС Линк данные об участии слушателя: факт посещения и время нахождения в вебинаре. Эти данные используются для отображения статуса прохождения вебинара в АСУО и дальнейшего учета в учебном процессе.
Получение данных о посещении вебинара
После завершения вебинара АСУО через API получает из МТС Линк данные об участии слушателей в мероприятии.

АСУО должна получить и сохранить:

1. факт участия слушателя в вебинаре;
2. время нахождения слушателя в вебинаре;
3. проставлении отметки, что информация получена из МТС Линк;
4. проставление посещения / непосещения в таблице слушателей потока;
5. учет посещения в результатах деятельности.


После получения данных АСУО проставляет отметку посещения в таблице слушателей по соответствующему очному мероприятию типа «Вебинар».
Учет посещения вебинара в «Результатах деятельности»
При получении из МТС Линк данных о посещении вебинара АСУО должна учитывать вебинар как выполненную активность слушателя, если данный вебинар выбран в дисциплине в разделе «Осваивается за счет сущностей». Данные должны использоваться для обновления результатов деятельности слушателя по соответствующей дисциплине.
Запись вебинара
Предполагаемый процесс работы с записью вебинара:

1. Если при создании вебинара в АСУО включен параметр «Предоставить слушателям запись вебинара», АСУО создает вебинар(через API) в МТС Линк с включенной записью.
2. Вебинар проводится на стороне МТС Линк.
3. После завершения вебинара МТС Линк формирует запись вебинара.
4. АСУО через API инициирует подготовку/конвертацию записи 
   1. либо проверяет статус подготовки записи
5. Пока запись не готова, АСУО может отображать в карточке мероприятия статус «запись готовится».
6. После готовности записи возможны два варианта:
   1. в ТЗ такая строчка: 

После завершения конвертации записи на стороне МТС Линк, ссылка на вебинар в очном мероприятии должна автоматически меняться на ссылку на просмотр записи вебинара. При этом запись должна храниться в АСУО.

2. Вариант 1. Хранение ссылки на запись
 АСУО получает из МТС Линк ссылку на просмотр записи и сохраняет ее в карточке очного мероприятия. Слушатели переходят к записи из АСУО по ссылке.
3. Вариант 2. Хранение файла записи в АСУО
 АСУО получает из МТС Линк сконвертированную запись или данные для ее скачивания, загружает файл в свое хранилище и отображает слушателям запись уже из АСУО.
4. Оба варианта?

7. В карточке очного мероприятия ссылка на вебинар заменяется ссылкой на запись.
8. Слушатели получают доступ к записи из АСУО

Синхронизация менеджеров/преподавателей АСУО с МТС Линк
Менеджер АСУО 
Менеджер АСУО → Админ конкретного вебинара МТС Линк

Менеджер с почтой (домен: ranepa.ru), создает очное мероприятие типа «Вебинар» в АСУО. Менеджер нужен МТС Линк до появления вебинара, чтобы от его имени создать мероприятие, поэтому мы не можем его просто зарегистрироваться на мероприятие.
В МТС Линк он должен быть сотрудником организации, потому что по API ID сотрудника организации используется для создания вебинара от имени сотрудника. В API роли сотрудников организации МТС линк: admin 
Логика:

1. Менеджер создает вебинар в АСУО.
2. АСУО синхронизирует пользователей:
   1. проверяет менеджера среди сотрудников организации МТС Линк по email.
      1. Если менеджер найден - вебинар создается в МТС Линк под его учетной записью.
      2. Если не найден - АСУО инициирует добавление/приглашение в организацию МТС Линк.

Важный момент по API: если менеджера нет среди сотрудников организации МТС Линк, АСУО может через API отправить ему приглашение в организацию. До подтверждения приглашения менеджером создание вебинара под его учетной записью может недоступно. (Вопрос?)

Преподаватель АСУО
Преподаватель АСУО → Лектор / ведущий конкретного вебинара МТС Линк
Преподаватель указывается в карточке очного мероприятия типа «Вебинар» в АСУО. (вопрос нужна ли эта роль?)
В МТС Линк преподавателя логично регистрировать на конкретный вебинар с ролью LECTURER, если это нужно
Но если преподавателю нужна не просто ссылка входа в конкретный вебинар, а кнопка бесшовного перехода из админки АСУО в портал/ЛК МТС Линк, то его, скорее всего, надо рассматривать не как обычного участника-контакт, а как пользователя/сотрудника организации МТС Линк.Прохождение вебинара

Бесшовная авторизация пользователей админки (менеджеров)  между АСУО и МТС Линк;
Для пользователей админки АСУО, участвующих в создании и управлении вебинарами (менеджер/преподаватель), должен быть реализован бесшовный переход из АСУО в МТС Линк без повторного ввода логина и пароля.
Бесшовный переход нужен для менеджеров, которые создают очные мероприятия типа «Вебинар» в АСУО и должны иметь возможность перейти в МТС Линк для работы с созданными вебинарами.
