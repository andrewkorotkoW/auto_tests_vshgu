Технический вопрос от Максима. Нужно уточнить, может ли использование интеграции с МТС Линк быть отдельной настройкой тенанта?
Причина: возможен сценарий, когда платформа используется партнёром, но интеграция оплачивается Академией. В таком случае у партнёра не должно быть доступа к интеграции Академии.
Нужно определить:
можно ли включать / выключать интеграцию с МТС Линк для конкретного тенанта;
можно ли для разных тенантов использовать разные токены / организации МТС Линк;
Кратко
Интеграция связывает вебинары АСУО с МТС Линк: вебинар создается в АСУО как очное мероприятие, проводится на платформе МТС Линк, а данные об участии слушателей, записи и статистика возвращаются обратно в АСУО для фиксации посещаемости и дальнейшего учета в учебном процессе.
Что делаем
создание вебинара в МТС Линк из карточки очного мероприятия в АСУО;
регистрация слушателей из АСУО на вебинар МТС Линк;
прохождение слушателями из АСУО вебинара МТС Линк по персональной ссылке;
получение из МТС Линк данных о посещении вебинара и времени нахождения слушателей;
получение, хранение и отображение записи вебинара по вебинарам, созданным из АСУО;
учет посещения вебинара в «Результатах деятельности» с учетом времени нахождения на вебинаре;
проверка доступа менеджеров и преподавателей в МТС Линк перед созданием вебинара;
отображение настроек МТС Линк в админке АСУО, чтобы менеджер мог управлять ключевыми настройками вебинара;
email-уведомления пользователей по вебинару средствами МТС Линк;
логирование действий интеграции на уровне БД по аналогии с external_requests_audit.
Создание вебинара
Вебинар создается в АСУО с помощью API МТС Линк как очное мероприятие типа «Вебинар». Если в карточке мероприятия включен параметр «Создать вебинар в МТС Линк», АСУО через API создает связанный вебинар на стороне МТС Линк.
См. методы API: создание Event и EventSession
Под какой учетной записью создается вебинар
Вебинар в МТС Линк создается под учетной записью менеджера / организатора, который выполняет создание вебинара в АСУО.
Перед созданием вебинара АСУО проверяет, что менеджер существует в организации МТС Линк и имеет права на создание вебинаров.
Если менеджер найден и права подтверждены, АСУО создает вебинар в МТС Линк.
Если менеджер не найден в организации МТС Линк или у него недостаточно прав, вебинар не создается. Пользователю показывается уведомление о необходимости проверить учетную запись и права в МТС Линк.
АСУО не может создавать учетные записи сотрудников МТС Линк через API, добавлять пользователей в организацию или отправлять приглашения сотрудникам автоматически. Настройка учетных записей и прав сотрудников выполняется на стороне МТС Линк.
Проверка доступа перед созданием
Перед созданием вебинара АСУО проверяет возможность создания вебинара в МТС Линк под учетной записью менеджера / организатора.
Проверка включает:
наличие пользователя в организации МТС Линк;
наличие прав на создание вебинара;
возможность указать пользователя владельцем / организатором создаваемого вебинара.

Если проверка успешна, АСУО создает вебинар в МТС Линк.

Если проверка неуспешна, АСУО не создает вебинар и показывает сообщение о невозможности создания вебинара. В сообщении нужно указать, что необходимо проверить учетную запись менеджера и его права в организации МТС Линк.
Учетные записи в МТС Линк
АСУО не должна самостоятельно создавать сотрудников/платные учетные записи в МТС Линк и не должна автоматически отправлять приглашение сотруднику в организацию МТС Линк. Если учетная запись менеджера или преподавателя отсутствует в МТС Линк, вопрос решается организационно: через администратора МТС Линк или обращение в поддержку.
Важно: АСУО не создает учетные записи сотрудников в МТС Линк автоматически.
Что добавляется / используется в карточке очного мероприятия «Вебинар»
Параметр «Создать вебинар в МТС Линк»
При включении этого параметра АСУО после сохранения мероприятия создает связанный вебинар в МТС Линк.
Параметр «Предоставить слушателям запись вебинара»
Параметр определяет, нужно ли после вебинара показывать запись слушателям и назначать ее на просмотр. При этом запись по вебинарам, созданным из АСУО, должна быть получена из МТС Линк и сохранена в АСУО.
Логика получения, хранения, добавления в базу материалов и срока доступности описана ниже в разделе «Запись вебинара».
Ссылка на вебинар
После создания вебинара МТС Линк возвращает ссылку, АСУО сохраняет ее в карточке очного мероприятия. Ссылка должна быть доступна в админке и на внешке тем пользователям, у которых есть права на просмотр/переход.
Часовой пояс
В расписании и карточке мероприятия нужно отображать часовую зону, чтобы пользователь понимал, в каком времени указан вебинар.
Важно: часовой пояс вебинара соответствует часовому поясу тенанта. Для глобальной организации используется UTC+3 / Москва.
Блок настроек МТС Линк в админке
Не зашиваем все настройки на бэке. Настройки, которые влияют на сценарий вебинара, должны быть доступны менеджеру в карточке очного мероприятия типа «Вебинар». Перечень настроек и комментарии приведены в разделе «Детальные настройки вебинара в админке».
См. также API и настройки МТС Линк: https://help.mts-link.ru/article/19615
Какие данные передаются в МТС Линк
АСУО передает через API:
название вебинара;
дату проведения;
время начала;
продолжительность;
часовой пояс тенанта;
данные менеджера/организатора;
данные преподавателя/лектора;
настройки доступа к вебинару;
настройки запуска вебинара;
настройки уведомлений;
настройки сценария вебинара;
настройки записи и конвертации записи, если применимо.
Важно: date_time_from формируется от времени очного мероприятия в АСУО с учетом часового пояса тенанта. Для глобальной организации используется UTC+3 / Москва. В интерфейсе расписания нужно показывать часовую зону.
Настройки сценария вебинара
Часть настроек вебинара должна быть доступна менеджеру в карточке очного мероприятия типа «Вебинар». Это настройки, которые меняют сценарий входа, запуска, допуска участников, чата, вопросов, демонстрации экрана и записи.
Подробный перечень настроек см. в разделе «Детальные настройки вебинара в админке».
Запуск и завершение вебинара
По запуску вебинара используем автозапуск. Вебинар на стороне МТС Линк должен стартовать за 10 минут до планового времени начала очного мероприятия, чтобы преподаватель и слушатели могли подключиться заранее. При этом в расписании АСУО показывается плановое учебное время из карточки очного мероприятия.
Важно: вебинар в МТС Линк запускается автоматически за 10 минут до планового времени начала очного мероприятия.
Вебинар не должен автоматически завершаться по расписанию. В АСУО передаем плановую дату, время и продолжительность, но фактическое завершение вебинара выполняет преподаватель/лектор вручную в МТС Линк. После фактического завершения АСУО забирает статистику посещений и запись.
Редактирование и удаление вебинара
Если менеджер редактирует очное мероприятие в АСУО, АСУО должна попытаться обновить связанный вебинар в МТС Линк через API. Если нужный метод API недоступен или МТС Линк возвращает ошибку, АСУО показывает пользователю понятное уведомление, что данные в МТС Линк не обновлены и требуется ручная проверка/обращение.
При удалении очного мероприятия в АСУО АСУО должна попытаться удалить или отменить связанный вебинар в МТС Линк, если это поддерживается API. Если удаление невозможно, нужно показать уведомление и зафиксировать ошибку в логах интеграции.

По API МТС мероприятие создается через две сущности: Event как техническая «оболочка» и EventSession как само мероприятие, куда приглашаются участники и ведущие. В документации также перечислены параметры доступа, времени, часового пояса, запуска, уведомлений и настроек модулей вебинара.
Для записи МТС Линк отдельно дает параметры конвертации: качество 720/1080 и view, который определяет состав MP4-файла: чат, вопросы, мини-чат, видео ведущих и т.д.

Презентация и материалы очного мероприятия
Если к очному мероприятию типа «Вебинар» в АСУО приложена презентация или иной учебный файл, АСУО передает этот файл в МТС Линк и прикрепляет его к связанному вебинару.

Передача выполняется только для файлов, приложенных к конкретному очному мероприятию в АСУО.

После создания вебинара в МТС Линк АСУО:
загружает файл в файловое хранилище МТС Линк;
прикрепляет файл к созданному мероприятию МТС Линк;
сохраняет в АСУО информацию о результате передачи файла.

Если передача файла в МТС Линк завершилась ошибкой, вебинар не блокируется. АСУО показывает пользователю уведомление, что вебинар создан, но файл презентации не был передан в МТС Линк. Ошибка фиксируется в логах интеграции.

Если презентация была добавлена вручную на стороне МТС Линк, обратная синхронизация такой презентации в АСУО в рамках текущей интеграции не выполняется.

После завершения вебинара презентация, приложенная к очному мероприятию в АСУО, хранится в Базе материалов рядом с записью вебинара по общей логике хранения материалов.
Регистрация слушателя из АСУО на вебинар МТС Линк
Слушатель АСУО → участник конкретного вебинара МТС Линк.
Слушатель — это участник вебинара. Его не нужно добавлять в организацию МТС Линк как сотрудника. Для него используется регистрация на конкретное мероприятие с ролью GUEST, которая является ролью по умолчанию в API регистрации. После регистрации МТС Линк возвращает уникальную ссылку входа в вебинар.
Логика регистрации
АСУО регистрирует слушателя сразу на конкретный вебинар через метод «Зарегистрировать на мероприятие» или массовую регистрацию списком.
В запросе передаем email и ФИО слушателя. Этого достаточно; дополнительные данные не требуются.
Если email уже раньше регистрировался на мероприятия организации, МТС Линк может использовать существующие данные.
Если email новый, МТС Линк создает контакт в разделе «Люди» и в ответе возвращает contactId и participationId.
АСУО хранит ID мероприятия МТС Линк, contactId/participationId и персональную ссылку участника, чтобы после вебинара получить статистику посещения и корректно связать данные с конкретным слушателем в АСУО.
До появления отдельного назначения слушателей на конкретное очное мероприятие регистрируем всех слушателей, которые назначены на поток/мероприятие по текущей логике АСУО. Дополнительные ограничения по количеству вебинаров/участников в рамках ТЗ считаем отсутствующими.
Доступность вебинаров в ИТ
Функционал создания и прохождения вебинаров МТС Линк должен быть доступен не только для потоков, но и для ИТ, если в ИТ используется очное мероприятие типа «Вебинар».
Логика создания вебинара, регистрации участников, перехода по персональной ссылке, получения статистики и записи применяется по тем же правилам, что и для вебинаров в составе потока.
Прохождение вебинара слушателем в АСУО
После назначения слушателя на очное мероприятие типа «Вебинар» АСУО регистрирует его как участника соответствующего вебинара в МТС Линк.
На внешке у слушателя вебинар должен отображаться как учебное мероприятие в составе программы/расписания. Слушателю должны быть доступны основные сведения о вебинаре:
название вебинара;
дата и время проведения с часовой зоной;
преподаватель/ведущий, если указан;
кнопка перехода в вебинар;
после завершения вебинара — ссылка/карточка записи, если запись предоставляется слушателям.
Кнопка перехода может быть доступна заранее. Если вебинар еще не начался или МТС Линк показывает страницу ожидания, это обрабатывается на стороне МТС Линк.
При переходе из АСУО слушатель направляется по своей персональной ссылке участника. Для слушателей отдельный SSO-флоу на стороне АСУО не реализуем: если настройки вебинара позволяют автоматический вход по ссылке, авторизация не нужна.
Уведомления
Email-уведомления по вебинару отправляются средствами МТС Линк через параметры API.
При регистрации слушателей и преподавателей на вебинар АСУО передает в МТС Линк параметр sendEmail=true. В этом случае МТС Линк отправляет письмо о регистрации на вебинар и ссылку на подключение.
При изменении/переносе вебинара АСУО передает в МТС Линк параметр sendEmail=true, если нужно отправить участникам письмо о переносе вебинара.
В шаблоне мероприятия АСУО может включать defaultRemindersEnabled=true, чтобы использовать стандартные напоминания МТС Линк за 1 день и за 15 минут до вебинара.
Важно: со стороны АСУО уведомления не дорабатываются. Используется только текущая механика уведомлений АСУО, если она уже применяется к очным мероприятиям.
То есть вебинар должен отображаться в расписании/личном кабинете пользователя в рамках текущей логики АСУО, а отдельные новые уведомления со стороны АСУО в рамках этой доработки не реализуются.
Получение данных о посещении вебинара
После завершения вебинара АСУО через API получает из МТС Линк данные об участии слушателей в мероприятии.
АСУО должна получить и сохранить:
факт участия слушателя в вебинаре;
время нахождения слушателя в вебинаре;
признак, что информация получена из МТС Линк;
отметку посещения / непосещения в таблице слушателей потока;
данные для учета посещения в результатах деятельности.
После получения данных АСУО проставляет отметку посещения в таблице слушателей по соответствующему очному мероприятию типа «Вебинар». Для таких отметок должен быть отдельный тип/статус: данные получены из МТС Линк.
Учет посещения вебинара в «Результатах деятельности»
При получении из МТС Линк данных о посещении вебинара АСУО должна учитывать вебинар как выполненную активность слушателя, если данный вебинар выбран в дисциплине в разделе «Осваивается за счет сущностей». Данные должны использоваться для обновления результатов деятельности слушателя по соответствующей дисциплине.
Учет делаем пропорционально времени нахождения слушателя на вебинаре относительно часов, указанных в дисциплине/учебном плане.
Пример: в дисциплине вебинар засчитывает 2 часа. МТС Линк вернул, что слушатель был на вебинаре 1 час. В результатах деятельности засчитываем 1 из 2 часов, то есть 50%.
Если слушатель посетил вебинар не полностью, недостающие часы могут быть дозачтены за счёт просмотра записи вебинара.
Для расчёта результата по вебинару АСУО учитывает суммарное время:
время нахождения слушателя на вебинаре онлайн;
время просмотра записи вебинара, если запись предоставлена слушателю и по ней доступна статистика просмотра.
Суммарно по вебинару слушателю не может быть засчитано больше часов, чем указано в дисциплине / учебном плане в разделе «Осваивается за счёт сущностей».

Пример: вебинар засчитывает 2 часа. Слушатель был на вебинаре онлайн 1 час. В «Результатах деятельности» сначала засчитывается 1 из 2 часов. Если позже слушатель посмотрел запись ещё на 1 час, АСУО дозасчитывает оставшийся час, и вебинар считается выполненным полностью.
Для реализации нужно:
получать из МТС Линк факт посещения и время нахождения;
сохранять отметку по мероприятию с признаком источника МТС Линк;
получать и сохранять статистику просмотра записи вебинара, если запись предоставлена слушателю;
учитывать суммарное время участия онлайн и просмотра записи при расчёте часов по вебинару;
при суммировании онлайн-участия и просмотра записи ограничивать результат плановой длительностью вебинара: если вебинар засчитывает 2 часа, слушателю не может быть засчитано больше 2 часов;
использовать связь вебинара с дисциплиной и количеством часов в «Осваивается за счёт сущностей», только если вебинар выбран в дисциплине.
Запись вебинара
Запись вебинара должна храниться в АСУО по вебинарам, созданным из АСУО. Не скачиваем произвольные записи из аккаунта/организации МТС Линк, если они не связаны с вебинарами АСУО.
Параметр «Предоставить слушателям запись вебинара» определяет, нужно ли после вебинара показывать запись слушателям и назначать ее на просмотр. При этом технически запись по вебинару, созданному из АСУО, должна быть получена и сохранена по общей логике.
Предполагаемый процесс работы с записью вебинара
Вебинар проводится на стороне МТС Линк.
После завершения вебинара МТС Линк формирует запись вебинара.
АСУО через API инициирует подготовку/конвертацию записи либо проверяет статус подготовки записи.
Пока запись не готова, АСУО может отображать в карточке мероприятия статус «запись готовится».
После готовности АСУО получает запись/ссылку на скачивание, сохраняет запись в своем хранилище и связывает ее с очным мероприятием.
В карточке очного мероприятия ссылка на вебинар после завершения может заменяться на ссылку/карточку просмотра записи вебинара.
Добавление записи в базу материалов
После получения записи из МТС Линк АСУО должна добавить запись в базу материалов 
Запись должна быть доступна в карточке мероприятия и в базе материалов по общей логике работы с материалами АСУО.
Если включен параметр «Предоставить слушателям запись вебинара», запись должна быть назначена/открыта слушателям для просмотра. Это нужно, чтобы в дальнейшем можно было учитывать статистику просмотра записи.
Отдельный раздел в админке со списком всех записей делать не нужно. Достаточно отображения записи в карточке мероприятия и хранения через базу материалов/папки в базе материалов.
Для записей вебинаров используется единая логика нейминга и размещения в Базе материалов.
Запись вебинара сохраняется в папку Базы материалов, соответствующую дате проведения вебинара. Название файла записи формируется по шаблону:
ГГГГ-ММ-ДД_Название вебинара_Поток_Запись
Если к очному мероприятию была приложена презентация, она сохраняется в той же папке рядом с записью вебинара. Название файла презентации формируется по шаблону:
ГГГГ-ММ-ДД_Название вебинара_Поток_Презентация`
Срок хранения записи
Важно: запись вебинара хранится в АСУО 3 месяца с даты завершения программы. После истечения срока запись архивируется по общей логике хранения материалов.
Настройки конвертации записи
Настройки конвертации записи: качество 720p, режим/состав записи — view=questions. Перед реализацией нужно сверить фактический состав записи с заказчиком и API МТС Линк.
Проверка доступа менеджеров и преподавателей в МТС Линк
Источник данных по пользователям — АСУО. Обратную синхронизацию из МТС Линк в АСУО не закладываем.
АСУО перед созданием вебинара только проверяет, что менеджер или преподаватель может быть использован в МТС Линк для создания или проведения вебинара. Если МТС Линк возвращает ошибку по пользователю или правам, АСУО показывает понятное уведомление и не создает учетную запись в МТС Линк самостоятельно.
Менеджер АСУО
Менеджер АСУО → администратор/организатор конкретного вебинара МТС Линк.
Менеджер создает очное мероприятие типа «Вебинар» в АСУО. Менеджер нужен МТС Линк до появления вебинара, чтобы от его имени создать мероприятие. В МТС Линк он должен быть сотрудником/администратором организации или иметь права, достаточные для создания вебинара через API.
Если при создании вебинара МТС Линк возвращает ошибку по менеджеру или правам, АСУО не создает учетную запись и не отправляет приглашение автоматически. Показываем модальное уведомление: нужно проверить учетную запись/права в МТС Линк или обратиться в поддержку.
Преподаватель АСУО
Преподаватель АСУО → лектор / ведущий конкретного вебинара МТС Линк.
Преподаватель указывается в карточке очного мероприятия типа «Вебинар» в АСУО. Если у мероприятия несколько преподавателей, нужно поддержать передачу нескольких преподавателей/лекторов, если это поддерживается API МТС Линк.

Для преподавателя возможны два сценария:
если преподавателю достаточно входа в конкретный вебинар, его можно регистрировать на вебинар как LECTURER и передавать персональную ссылку/инвайт;
если преподавателю нужен доступ в личный кабинет/портал МТС Линк, он должен иметь учетную запись/доступ на стороне организации МТС Линк. В этом случае вход происходит уже на стороне МТС Линк.

МТС Линк отправляет преподавателю email-уведомление средствами API, если АСУО при регистрации/обновлении передает соответствующие параметры отправки уведомлений.
Слушатель АСУО
Слушатель АСУО → GUEST на конкретном вебинаре МТС Линк.
Слушатель не становится сотрудником организации МТС Линк. АСУО регистрирует его на конкретный вебинар, сохраняет персональную ссылку и использует ее для перехода из АСУО.
Ролевая модель
Базовое сопоставление ролей:
менеджер/администратор АСУО, который создает мероприятие, — владелец/организатор/администратор вебинара на стороне МТС Линк;
преподаватель/лектор мероприятия — роль LECTURER в МТС Линк;
слушатель — роль GUEST в МТС Линк.

Права пользователей:
слушатель должен иметь право только подключиться к вебинару и участвовать в нем как гость;
преподаватель/лектор должен иметь права на проведение вебинара: запуск/ведение, демонстрация, работа с участниками, завершение вебинара;
администратор/менеджер должен иметь права на создание, изменение, удаление вебинара и просмотр служебной информации в рамках своих прав в АСУО и МТС Линк.
Бесшовный переход / авторизация пользователей
Для слушателей отдельный SSO-флоу на стороне АСУО не реализуем. При назначении слушателя на вебинар АСУО регистрирует его в МТС Линк через API, получает персональную ссылку участника и сохраняет ее у себя. При переходе слушатель открывает вебинар по этой персональной ссылке.
Для преподавателя/лектора основная точка входа — АСУО: преподаватель видит вебинар в карточке очного мероприятия / расписании и переходит в МТС Линк по ссылке из АСУО. Дополнительно МТС Линк может отправлять преподавателю письмо и событие в календарь средствами своих уведомлений.
Для администратора/менеджера переход возможен из админки АСУО в связанный вебинар или в личный кабинет МТС Линк. Отдельного документированного SSO-флоу в API МТС Линк не закладываем. Если у заказчика настроен корпоративный SSO на домене МТС Линк, например ranepa.mts-link.ru, то вход в личный кабинет МТС происходит на стороне МТС Линк через их SSO.
Логирование
Должно быть логирование действий интеграции. Отдельный внешний интерфейс логов в рамках этой доработки не делаем, так как раздел логов лучше выносить в отдельную фичу. Сейчас журналируем на уровне БД по аналогии с external_requests_audit.
Логировать нужно минимум:
создание вебинара в МТС Линк;
обновление вебинара;
удаление/отмена вебинара;
регистрацию слушателей/преподавателей на вебинар;
получение и сохранение персональных ссылок участников;
получение статистики посещений;
получение/конвертацию/сохранение записи;
ошибки API МТС Линк и текст/код ошибки;
показ пользователю модального уведомления при ошибках интеграции.
