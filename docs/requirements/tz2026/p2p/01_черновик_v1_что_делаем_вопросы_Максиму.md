Что делаем
Дорабатываем существующее Практическое задание для сценария взаимопроверки.

На текущий момент наше понимание такое: новый тип активности не создаётся, а взаимопроверка реализуется как дополнительный режим работы существующего ПЗ.

В карточке ПЗ добавляется настройка: «Включить взаимопроверку»
При включении настройки ПЗ работает не по стандартной схеме проверки, а по сценарию peer-to-peer:

1. слушатель отправляет работу;
2. работа становится доступна назначенным проверяющим;
3. проверяющие заполняют форму оценки по критериям (тесту);
4. система агрегирует результаты проверок: например, если критерий представлен вопросом со шкалой оценки, то рассчитывается средний балл по этому критерию на основании всех проверок;
5. слушатель во внешнем интерфейсе видит результаты по своей работе: оценки по критериям и общую среднюю оценку;
6. неавторизованный пользователь по ссылке видит только работу и форму критериев (тест), без доступа к внешнему интерфейсу и статистике;
7. преподавателю и назначенному проверяющему доступны статистика проверок, результаты по критериям и возможность при необходимости выставить итоговый зачёт/незачёт и балл;
8. за проведённую проверку может быть выдан сертификат.


В процессе участвуют несколько ролей:

* слушатель — сдаёт работу и может участвовать в проверке работ других слушателей;
* проверяющий / преподаватель — пользователь, которому доступна проверка работ по критериям (тесту), просмотр результатов и статистики, а также выполнение действий по итогам проверки в рамках назначенных прав;
* администратор — настраивает параметры взаимопроверки (включение механики, критерии оценки, правила назначения проверяющих, ограничения и условия выдачи сертификатов), управляет доступами и имеет полный доступ к статистике и результатам проверок;
* неавторизованный пользователь — может получить ссылку на конкретную работу и выполнить проверку по тесту с вопросами без входа в систему.


Вопросы к Максиму по блоку «Что делаем»:

* Система агрегирует результаты взаимопроверки по заданным критериям. Нужно уточнить, кто может выставлять итоговый результат (зачёт/незачёт, оценку по пятибалльной шкале): только преподаватель, преподаватель и проверяющий или другие роли.
* В обычном ПЗ есть сценарий возврата работы на доработку. Нужно уточнить, будет ли этот сценарий использоваться при взаимопроверке и как он должен работать: может ли преподаватель вернуть работу на доработку и должен ли после повторной сдачи запускаться новый цикл взаимопроверки.
* Нужно уточнить, как будет работать выбор проверяющих: можно ли назначать проверяющих только из участников текущего потока или также выбирать пользователей из всей системы.
* Нужно определить критерий завершения процесса взаимопроверки: достаточно ли достижения требуемого количества проверок или завершение связано с выставлением итогового результата (зачёт/незачёт).

Критерии оценки
Критерии оценки понимаем как конструктор тестов / форму оценки.
Каждый вопрос в форме — это отдельный критерий оценки.
Пример:

* вопрос со шкалой 1–10 — количественный критерий;
* одиночный выбор — критерий с одним вариантом ответа;
* множественный выбор — критерий с несколькими вариантами;
* текстовое поле — качественный комментарий / текстовый критерий.

По ответам на критерии система считает результат:

* среднее значение по каждому критерию (например, для критерия - вопроса со шкалой 1–10 рассчитывается средний балл по всем проверкам);
* общую среднюю оценку по работе (средний результат по всем критериям и всем проведённым проверкам);
* количество проверок (сколько проверяющих фактически оценили работу);

Вопросы к Максиму:

* Критерии оценки настраиваются как тест в карточке активности при включённой взаимопроверке?
* Как отображать результаты по текстовым критериям? Для них нельзя посчитать среднее значение так же, как для числовых оценок. Нужен ли отдельный экран (или отдельный блок в статистике), где будут выводиться все текстовые ответы проверяющих и качественная обратная связь по работе?

Настройки взаимопроверки
Где включается взаимопроверка
В карточке ПЗ добавляется тумблер:
«Включить взаимопроверку»
При выключенном тумблере ПЗ работает как сейчас.
При включенном тумблере ПЗ переходит в режим взаимопроверки и становятся доступны связанные с ним настройки и статистика.
Где настраиваются проверяющие
Есть текущая проблема: сейчас преподаватели и проверяющие в ПЗ назначаются в карточке активности.
Сейчас есть ограничение: одно и то же ПЗ нельзя добавить в программу/поток дважды, только один раз. Нужно понять, это техническое ограничение или бизнес-правило.
Вопрос: Но для взаимопроверки нужно определить, должна ли она быть привязана к потоку, поскольку от этого зависит логика назначения и работы проверяющих:

* слушатели конкретного потока;
* преподаватели конкретного потока;
* внешние пользователи по ссылке для конкретной работы;
* назначенные проверяющие.

Предлагаемое решение:

* базовый признак взаимопроверки хранить в карточке ПЗ;
* преподавателей и назначенных проверяющих настраивать в самом ПЗ;
* слушателей, участвующих во взаимопроверке, определять в рамках конкретного потока; при этом выбор для проверки между слушателями может выполняться как в автоматическом режиме (система сама назначает работы на проверку), так и в ручном режиме (назначение выполняет администратор);
* проверки по ссылке можно настраивать как в карточке ПЗ, так и в потоке, продублировав эту возможность в обоих местах для удобства использования;
* итоговое разделение настроек между ПЗ и потоком требует дополнительного обсуждения.


Кто участвует в проверке
Взаимопроверка должна поддерживать несколько типов проверяющих:

1. Слушатель потока
Может проверять работы других слушателей. Свою работу видеть на проверку не должен (уточнить)
2. Неавторизованный пользователь
Переходит по личной ссылке и видит только интерфейс проверки: работу и форму критериев (сам тест). ЛК, список работ и статистику не видит.
3. Преподаватель
Видит статистику проверок, оценки по критериям и может выставить итоговый зачёт/незачёт и балл, если это подтверждается заказчиком.
4. Проверяющий из настроек ПЗ
Видит статистику проверок, оценки по критериям и может выставить итоговый зачёт/незачёт и балл, если это подтверждается заказчиком.

Статистика
Статистика должна быть доступна разным категориям пользователей и отображать данные в зависимости от их роли.

На внешке
Для слушателя (чью работу проверяют):

* статус проверки работы;
* итоговую оценку;
* результаты по отдельным критериям оценки.


Для слушателя, который проверяет чужие работы:

* количество доступных работ для проверки;
* статус назначенных на проверку работ;


Для неавторизованного пользователя ничего дополнительно не показываем. После отправки формы проверки доступ к результатам, статусам и статистике не предоставляется.

Для преподавателя и проверяющего в админке и на внешке :

* количество выполненных проверок;
* кто сдал работу;
* кто проверял;
* средние значения по каждому критерию
* итоговая оценка;
* зачёт/незачёт;

Сертификаты
Сертификат выдается не за сдачу ПЗ, а за проведенную проверку.
Используем текущую механику создания и отправки сертификатов.

Индивидуальные ПЗ в режиме самопроверки
Индивидуальные назначения в тз и смете отдельно не обсуждались.

Возврат на доработку
В текущем ПЗ есть сценарий возврата работы на доработку.
Для взаимопроверки предлагаем на первом этапе его не использовать.
Логика проще:

1. слушатель отправил работу;
2. проверяющие заполнили критерии;
3. система посчитала результат;
4. преподаватель посмотрел статистику;
5. результат стал доступен слушателю.
