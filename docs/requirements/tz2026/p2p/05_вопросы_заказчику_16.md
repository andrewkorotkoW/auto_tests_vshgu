Вопросы заказчику по взаимопроверке P2P
Где будет настраиваться взаимопроверка.
Вариант 1. В текущей карточке ПЗ — как один из способов оценивания. Там же настраиваются критерии 
Вариант 2. Отдельный новый тип активности «ПЗ с взаимопроверкой».
Вариант 3. Взаимопроверка включается уже при назначении обычного ПЗ в конкретный поток.

Администратор, Администратор организации, Поддержка, Менеджерам

Проверяющий из карточки ПЗ
Видит список работ по ПЗ, открывает конкретную работу, видит ответы по критериям, статистику и комментарии, выставляет итоговую оценку
Слушатель-проверяющий
Видит назначенные ему чужие работы, открывает работу и заполняет форму критериев. Итоговую оценку не выставляет. Может получить сертификат за проверку определенного количества работ
Неавторизованный пользователь по ссылке
Видит только конкретную работу и форму критериев. Не видит список работ, общую статистику и итоговую оценку
Автор работы
Видит статус своей работы, итоговую оценку и согласованный состав результатов по критериям (или только итоговую оценку)



1. Как агрегировать результаты проверок
Итоговую оценку система автоматически не выставляет. Она должна быть выставлена вручную одним из пользователей, добавленных в карточке ПЗ в список «Проверяющие» (они все могут выставить итоговую оценку).

Нужно определить, как система должна подготовить статистику по результатам нескольких проверок для принятия итогового решения.

Предлагаемый вариант:

по каждому числовому критерию в столбце «Полученные значения» показывать все оценки проверяющих, например 4, 5, 4;
в столбце «Агрегированное значение» рассчитывать их среднее арифметическое с округлением до одного знака, например 4,3;
текстовые ответы и комментарии выводить списком;
агрегированные значения использовать только как статистику для проверяющего, который вручную выставляет итоговую оценку.

Пример: по критерию получены оценки 4, 5 и 4. Система показывает среднее значение 4,3, после чего проверяющий вручную выставляет итоговую оценку за работу.

2. Где должны находиться настройки
Разработчик предлагает разместить все настройки на уровне назначения ПЗ в конкретный поток, поскольку одно ПЗ может использоваться в разных потоках по-разному.

Предлагаем разделить настройки по таблице выше:

постоянные настройки самой активности хранить в карточке ПЗ;
параметры конкретного запуска и распределения хранить в потоке;
реальные назначения, результаты и ссылки показывать в списке работ.

Подтверждаете такое разделение?

Отдельно подтвердите: базовое разрешение внешней проверки по ссылке должно находиться в карточке ПЗ, а конкретные ссылки должны формироваться в потоке для конкретных работ?


3. Как должны работать ручной и автоматический режимы
В ТЗ предусмотрены оба режима.

Предлагаем зафиксировать следующую логику:

ручной режим — администратор для каждой сданной работы назначает конкретных проверяющих; можно назначить несколько проверяющих, но нельзя назначить слушателю его собственную работу;
автоматический режим — слушателям показывается общая очередь доступных чужих работ; после получения необходимого количества проверок работа исчезает из очереди.

Подтверждаете такую разницу между режимами?

Что должна делать система, если работы проверяются слишком медленно и к установленному сроку не набрали необходимое количество проверок?


4. Кто из проверяющих может выставлять итоговую оценку
Итоговую оценку могут выставлять только пользователи, выбранные в карточке ПЗ в поле «Проверяющие».

Нужно выбрать один вариант:

Для конкретного проверяющего дополнительно включается признак «Может выставлять итоговую оценку».
Все пользователи из поля «Проверяющие» автоматически могут выставлять итоговую оценку, отдельный признак не используется.

Предлагаем второй вариант: все проверяющие из карточки ПЗ могут выставлять итоговую оценку без отдельного флага.

Если проверяющих несколько, нужно уточнить:

может ли любой из них первым выставить итоговую оценку;
могут ли остальные изменить уже выставленную оценку;
5. Список работ для администратора и проверяющих
Подтверждаете следующий процесс?

В списке работ отображаются:

автор работы;
статус сдачи и взаимопроверки;
количество назначенных и выполненных проверок;
итоговая оценка;
действие «Открыть работу».

При открытии работы администратор или проверяющий видит:

ответ и приложенные файлы;
результаты всех проверок;
ответы по каждому критерию;
агрегированные показатели и комментарии;
поле для итоговой оценки — только для проверяющих из карточки ПЗ.

Где должен располагаться этот список для проверяющих: в административном интерфейсе, в пользовательском интерфейсе или в обоих интерфейсах с одинаковой логикой?


6. Внешняя проверка без авторизации
Подтверждаете, что неавторизованный пользователь по ссылке видит только одну конкретную работу и форму критериев?

Нужно уточнить:

ссылка формируется отдельно для каждой работы или отдельно для каждой пары «работа — внешний проверяющий»;
одна и та же ссылка может быть использована только один раз или несколькими людьми;
где администратор создаёт, копирует и отключает ссылку;
нужно ли ограничивать срок действия ссылки.

Предлагаемый вариант первого этапа: персональная одноразовая ссылка для конкретной работы и конкретной внешней проверки.


7. Возврат работы на доработку
Если один из проверяющих возвращает работу на доработку, проверка этой работы приостанавливается у остальных.

Что должно происходить после повторной сдачи?

Запускается новый цикл взаимопроверки, а предыдущие проверки сохраняются только в истории.
Продолжается старый цикл и сохраняются ранее полученные результаты.
Предыдущие проверки полностью сбрасываются.

Кто может вернуть работу на доработку: любой проверяющий из карточки ПЗ или также слушатель-проверяющий?


8. Когда можно выставлять итоговую оценку
В какой момент проверяющий из карточки ПЗ может выставить итоговую оценку?

только после получения установленного количества проверок;
после окончания срока проверки, даже если нужное количество проверок не собрано;
в любой момент после сдачи работы, в том числе до завершения взаимопроверки.

Предлагаемый вариант: итоговая оценка становится доступна после получения необходимого количества проверок либо после завершения установленного срока.


9. Что видит автор работы
После выставления итоговой оценки автору работы можно показать:

итоговую оценку;
агрегированные значения по критериям;
распределение ответов по вариантам;
текстовые комментарии;
отдельные оценки каждого проверяющего;
ФИО проверяющих.

Какие именно данные должен видеть автор работы? Должны ли результаты проверок быть анонимными?


10. Что видит слушатель, который проверял чужую работу
После отправки своей проверки слушатель-проверяющий должен видеть:

только собственные ответы по критериям;
собственные ответы и агрегированную статистику;
собственные ответы и итоговую оценку по чужой работе после её выставления.

11. Прогресс до сертификата за проверки
Нужно определить, где показывать прогресс «Проверено X из K» и нужно ли его показывать?:

в общем списке ПЗ;
только внутри конкретного ПЗ;
и в общем списке, и внутри ПЗ.

Предлагаемый вариант: краткий прогресс показывать в общем списке ПЗ, а подробный список выполненных и оставшихся проверок — внутри конкретного ПЗ.

Дополнительно нужно уточнить:

объединять ли прогресс до сертификата с общей статистикой пользователя по всем проверкам;
если пользователь состоит в нескольких потоках, считать прогресс отдельно по каждому ПЗ в каждом потоке или показывать общий прогресс;
сертификат выдаётся после выполнения всех назначенных проверок в рамках одного ПЗ или по общему количеству проверок в системе.


12. Роль преподавателя
Подтверждаете, что преподаватель в рамках P2P не является отдельной управляющей ролью и используется преимущественно для отображения во внешнем интерфейсе?

Все действия по проверке, просмотру статистики и выставлению итоговой оценки выполняют пользователи из поля «Проверяющие» в карточке ПЗ.


13. Критерии оценки и изменение формы
Нужно уточнить:

для каждого ПЗ создаётся отдельная форма критериев;
нужен ли стандартный набор критериев, который администратор может использовать как шаблон;
можно ли использовать существующий конструктор тестов/опросов как основу;
какие лишние настройки теста нужно скрыть;
можно ли изменять критерии после начала взаимопроверки.

Предлагаемый вариант: после получения первой проверки редактирование текущей версии критериев блокируется либо создаётся новая версия, а старые ответы продолжают относиться к прежней версии.


14. Отключение взаимопроверки после запуска
Можно ли отключить взаимопроверку, если по ПЗ уже есть сданные работы или выполненные проверки?

Предлагаемый вариант: после начала взаимопроверки настройку нельзя просто выключить. Администратор может только завершить или отменить конкретный запуск в потоке с сохранением истории.
