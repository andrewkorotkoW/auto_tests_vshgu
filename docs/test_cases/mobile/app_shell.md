# Тест-кейсы: mobile/app_shell (Android-оболочка «ДПО ПА»)

**Чек-лист заблокирован до появления dev-сборки apk; на проде не проходить.**

| Параметр | Значение |
|---|---|
| Область | Android-оболочка `ru.gosedu.vshgu` (WebView, `com.ranepa.gspm.MainActivity`), ручной прогон |
| Стенд | develop (dev-сборка apk с адресом `portal-develop.d2.devspark.ru` — запрошена у разработчиков, ожидается) |
| Роли | user |

Ручные кейсы, автотестами не покрыты (оболочка — одноразовый WebView, отдельный Appium-проект не
окупается — см. `docs/plans/2026-10-06_mobile_android_mission.md`). Путь к apk передаётся через
переменную окружения `MOBILE_APK`, сам файл в git не коммитится.

### TC-MOBILE-APP-001 Установка и первый запуск, системный запрос разрешения на уведомления
- Приоритет: high   Тип: manual   Роли: user
- Предусловия: dev-сборка apk, окружение develop; путь к apk — переменная окружения `MOBILE_APK`; устройство/эмулятор без ранее установленного пакета `ru.gosedu.vshgu`
| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Установить apk из `MOBILE_APK`, запустить приложение первый раз | Приложение запускается, открывается экран `WebView` без крашей |
| 2 | Дождаться системного диалога запроса разрешения `POST_NOTIFICATIONS` | Диалог показан при первом запуске; оба варианта ответа («Разрешить»/«Запретить») не вызывают краш |
| 3 | После ответа на диалог проверить открывшийся экран | Загружается страница входа develop-окружения (`/auth/main?uri-callback=/`) |

### TC-MOBILE-APP-002 Вход через WebView теми же учётными данными, что и в вебе
- Приоритет: high   Тип: manual   Роли: user
- Предусловия: dev-сборка apk, окружение develop; учётная запись пользователя, созданная/доступная на develop (те же данные, что используются в веб-тестах)
| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | На экране входа ввести логин/пароль учётной записи, используемой в веб-тестах на develop | Авторизация проходит успешно, без ошибок WebView |
| 2 | Проверить, что сессия сохраняется после входа | После входа приложение переходит на домашний экран портала (develop), повторного запроса логина нет |

### TC-MOBILE-APP-003 Список назначенных программ после входа
- Приоритет: high   Тип: manual   Роли: user
- Предусловия: dev-сборка apk, окружение develop; пользователю назначена хотя бы одна программа
| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Войти и открыть список программ (`/my-programs`) | Список загружается внутри WebView, назначенные программы отображаются |
| 2 | Открыть карточку одной из программ | Карточка программы открывается, вёрстка не выглядит сломанной (как в десктопной версии портала) |

### TC-MOBILE-APP-004 Загрузка файла в практическое задание через камеру
- Приоритет: high   Тип: manual   Роли: user
- Предусловия: dev-сборка apk, окружение develop; разрешение `CAMERA` разрешено (или будет запрошено по шагу), доступно практическое задание с загрузкой файла
| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | В активити с практическим заданием нажать загрузку файла, выбрать «Камера» | Если разрешение `CAMERA` не выдано — показан системный запрос разрешения |
| 2 | Сделать снимок и подтвердить его использование | Снимок передаётся из системной камеры в WebView через `FileProvider`, файл прикладывается к заданию |
| 3 | Отправить задание на проверку | Файл успешно загружен, задание переходит в статус «отправлено» |

### TC-MOBILE-APP-005 Загрузка файла в практическое задание через галерею
- Приоритет: high   Тип: manual   Роли: user
- Предусловия: dev-сборка apk, окружение develop; разрешение `READ_MEDIA_IMAGES` разрешено (или будет запрошено по шагу), в галерее устройства есть хотя бы одно изображение, доступно практическое задание с загрузкой файла
| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | В активити с практическим заданием нажать загрузку файла, выбрать «Галерея» | Если разрешение `READ_MEDIA_IMAGES` не выдано — показан системный запрос разрешения |
| 2 | Выбрать изображение из галереи | Файл передаётся в WebView, прикладывается к заданию |
| 3 | Отправить задание на проверку | Файл успешно загружен, задание переходит в статус «отправлено» |

### TC-MOBILE-APP-006 Кнопка «назад»: навигация по истории WebView и выход из приложения на корневом экране
- Приоритет: medium   Тип: manual   Роли: user
- Предусловия: dev-сборка apk, окружение develop; пользователь залогинен, перешёл на несколько экранов вглубь (например, программа → активити)
| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Находясь в карточке активити, нажать системную кнопку/жест «назад» | Происходит переход на предыдущий экран WebView (история браузера), без выхода из приложения |
| 2 | Повторять «назад» до возврата на корневой экран (список программ/домашний экран) | Каждый шаг возвращает на один экран назад по истории |
| 3 | На корневом экране нажать «назад» ещё раз | Приложение закрывается (сворачивается/завершается), краша нет |

### TC-MOBILE-APP-007 Поведение без сети: `offline.html` вместо белого экрана, восстановление сети
- Приоритет: high   Тип: manual   Роли: user
- Предусловия: dev-сборка apk, окружение develop; возможность отключить сеть на устройстве/эмуляторе (авиарежим или Wi-Fi/моб. данные выкл.)
| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Запустить приложение с выключенной сетью (или отключить сеть во время работы приложения) | Показывается собственный экран оболочки `assets/offline.html` («Нет подключения»), а не белый экран |
| 2 | Проверить вид экрана `offline.html` | Экран читаемый, без краша WebView; это отдельная проверка от известного замечания — при ошибке SSL (устаревшее доверенное хранилище) оболочка на некоторых устройствах показывает белый экран вместо `offline.html` — зафиксировать расхождение, если воспроизведётся |
| 3 | Включить сеть обратно | Приложение восстанавливает соединение и загружает develop-окружение без переустановки/перезапуска |

### TC-MOBILE-APP-008 Возврат из фона (foreground после сворачивания)
- Приоритет: medium   Тип: manual   Роли: user
- Предусловия: dev-сборка apk, окружение develop; пользователь залогинен и находится на любом экране портала
| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Свернуть приложение (кнопка «домой» / переключение задач) и подождать 1-2 минуты | Приложение уходит в фон без краша |
| 2 | Вернуть приложение на передний план | Экран восстанавливается в том же состоянии (тот же экран, сессия сохранена), повторного входа не требуется |

### TC-MOBILE-APP-009 Открытие внешних ссылок
- Приоритет: medium   Тип: manual   Роли: user
- Предусловия: dev-сборка apk, окружение develop; на экране портала есть внешняя ссылка (не на `portal-develop.d2.devspark.ru`), например в контенте программы или в футере
| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Нажать на внешнюю ссылку (ведущую за пределы develop-окружения портала) | Открытый вопрос: неизвестно, открывается ли ссылка внутри оболочки (во встроенном WebView) или передаётся в системный браузер устройства — зафиксировать фактическое поведение при прохождении |
| 2 | Вернуться из открытой ссылки (назад/закрыть браузер) | Возврат в приложение не теряет состояние/сессию портала |

### TC-MOBILE-APP-010 Получение и обработка push-уведомления
- Приоритет: medium   Тип: manual   Роли: user
- Предусловия: dev-сборка apk, окружение develop; разрешение `POST_NOTIFICATIONS` выдано (см. TC-MOBILE-APP-001); пользователю отправлено/назначено событие, генерирующее уведомление (например, через раздел уведомлений портала `/portal-notifications`)
| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Дождаться (или спровоцировать через API/портал) push-уведомление, пока приложение свёрнуто или закрыто | Системное уведомление показывается в шторке устройства |
| 2 | Нажать на уведомление | Приложение открывается (из фона или с холодного старта) и переходит на релевантный экран портала develop-окружения |
