«Синхронизация вебинара» на оба случая. Детали — docs/test_cases/mts_link/16_prod_safe_run.md.

**12.11.2026 — автотест удалён.** Предпосылка «дата в прошлом = начался» больше не работает: создание
и обновление с прошлой датой сами дают 422 (другое правило — валидация даты, см.
test_create.py::test_creating_webinar_in_the_past_is_rejected). Проверка «честно»: создан вебинар
на +2 минуты, дождались реального наступления date_from по часам ЛМС — `PUT` на имя прошёл 200, не
заблокирован. Но это тоже не ответ по существу: «начало вебинара» в терминах продукта — это когда
ведущий реально запустил трансляцию в МТС Линк (или сработал автостарт сессии МТС Линк, который по
разведке 29.10.2026 наступает за ~10 минут ДО date_from в ЛМС, а не после), не наступление времени по
часам ЛМС. Честно проверить можно только с реально стартовавшей сессией МТС Линк — ручной шаг, как
TC-MTS-059…075 (посещение/запись, см. `10_attendance.md`/`12_recording.md`).
