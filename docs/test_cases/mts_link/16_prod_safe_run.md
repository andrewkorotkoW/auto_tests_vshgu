## Правила прогона (предусловия для всех кейсов)

- Токен интеграции **не менять и не удалять**: рабочий токен единственный, без него встанут вебинары
  всей организации. Проверяем только невалидные токены (TC-MTS-097…099) — они не сохраняются.
- Все мероприятия — с префиксом `[ТЕСТ]` в названии, длительность 5–30 минут.
- Лектор — пользователь ЛМС с настоящей почтой Веры (согласовано, Вера уже в портале): ей приходят
  настоящие приглашения МТС Линк. Слушатели — тестовые пользователи, регистрируются на
  `vshgu_<hmac>@mail.ru`, писем им не уходит.
- В запросах к МТС Линк — только id, появившиеся на платформе в ходе прогона (`mts_event_id`,
  `mts_event_session_id`, `mts_participation_id`, `mts_file_id`, `mts_webhook_id`). Чужие id из кабинета
  МТС Линк не трогать.
- Проверки в БД — SQL в pgAdmin (текст запросов ниже). Запросы в МТС Линк и ответы смотреть в
  `external_requests_audit` (`external_system = 'mts_link'`).
- Открытый вопрос к заказчику: лектора регистрировать по настоящей почте (сейчас так: роль ADMIN,
  `sendEmail=true`) или на `vshgu_…@mail.ru`. Ожидания про письмо лектору помечены «ждёт ответа заказчика».
- **Перед мержем** (TC-MTS-110): `ClientServiceProvider::isMtsLinkLive()` должен вернуть нормальное
  условие — на ветке он всегда `true`.

Полезные запросы:

```sql
-- настройка тенанта: токен/вебхук до и после каждого шага
SELECT tenant_organization_id, is_enabled, mts_webhook_id, left(token, 6) AS token_head, updated_at
FROM tenant_mts_link_configurations;

-- вебинары прогона (PK — mts_webinar_id; offline_entity_id = id элемента расписания ЛМС)
SELECT mts_webinar_id, offline_entity_type, offline_entity_id, mts_event_id, mts_event_session_id,
       webinar_status, participants_sync_status, lecturers_sync_status, files_sync_status,
       stats_sync_status, record_status, record_link, actual_started_at, actual_finished_at,
       created_at, updated_at, deleted_at
FROM mts_webinars ORDER BY mts_webinar_id DESC;

-- слушатели / лекторы / файлы по вебинару (:id = mts_webinar_id)
SELECT mts_webinar_participant_id, assignment_id, schedule_items_visitor_id, mts_participation_id,
       mts_contact_id, registered_email, join_link, is_visited, time_spent_seconds,
       actual_visited_percent, stats_synced_at, deleted_at
FROM mts_webinar_participants WHERE mts_webinar_id = :id ORDER BY mts_webinar_participant_id;
SELECT mts_webinar_lecturer_id, user_id, mts_participation_id, join_link, deleted_at
FROM mts_webinar_lecturers WHERE mts_webinar_id = :id ORDER BY mts_webinar_lecturer_id;
SELECT mts_webinar_file_id, material_id, mts_file_id, sync_status, error_message
FROM mts_webinar_files WHERE mts_webinar_id = :id ORDER BY mts_webinar_file_id;

-- что ушло в МТС Линк за последние 30 минут (request/response_body — jsonb, нужен ::text)
SELECT created_at, method, uri, http_status_code,
       left(request_body::text, 300) AS req, left(response_body::text, 300) AS resp
FROM external_requests_audit
WHERE external_system = 'mts_link' AND created_at > now() - interval '30 minutes'
ORDER BY created_at DESC;
```
