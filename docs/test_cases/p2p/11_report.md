| Параметр | Значение |
|---|---|
| Область | ручная проверка отчёта PDF/Word по взаимопроверке (без автотеста на Этапе 1) |
| Стенд | develop (см. README §13) |
| Роли | admin, reviewer, user |

Отчёт — краткое ТЗ п.1.1.3.4, детализация — 03 §11 (заказчик не подтвердил состав/формат/место
скачивания, 04 §11). Все кейсы ручные, `- Автотест:` не пишется (мнение мисcии: «Отчёт PDF/Word...
— ручные»). Важно: ни один из вопросов заказчику про отчёт не входит в перечень 16 пунктов
`05_вопросы_заказчику_16.md` — это открытые вопросы из 04 §11, отдельно не занумерованные заказчиком.

**17.11.2026 — предварительная разведка на p2p-prototype (попутно с частью 10; полный проход части 11
ещё впереди), подтверждено:**
- Маршруты (таблица `/routes`): штатные — `POST /stream-contents/{stream_content}/peer-review-report/
  regenerate` (отчёт по потоку, ответ 202 `{"queued": true}`), `GET .../peer-review-report/download`
  (422 «Отчёт ещё не сформирован», пока не собран; после сборки — 200 с записью экспорта, НЕ файл),
  `POST /homework-answers/{answer}/peer-review-report/regenerate` (отчёт по одной работе, 201 с записью
  экспорта сразу; кнопка «Пересобрать отчёт (PDF)» на админской странице работы); авторский —
  `GET /my/homework-answers/{answer}/peer-review-report`.
- **TC-P2P-077 подтверждён**: отчёт потока привязан к `stream_content_id` (назначению ПЗ в поток), а не
  к карточке ПЗ.
- **TC-P2P-078 подтверждён**: отчёт потока — zip (экспорт `type: 33`), внутри по каждой сданной работе
  PDF + DOCX («Отчёт_взаимопроверка_<answer_id>.pdf/.docx»); отчёт по одной работе — PDF (экспорт
  `type: 31`, «Отчёт_взаимопроверка_<answer_id>_full_<timestamp>.pdf», подзаголовок «Полный состав»).
- **TC-P2P-079 (состав) снят с реального PDF по работе 46**: Автор, Статус («Практическое задание
  проверено»), Программа, Практическое задание, Поток, Назначено проверок, Выполнено проверок,
  Средняя оценка по форме, Итог; раздел «Проверяющие» (ФИО — оценка по форме); таблица «Критерии»
  (Критерий / Среднее / Комментарии списком). Гистограмм по вариантам choice-критериев в PDF НЕТ
  (в UI/API они есть — 07_aggregation.md).
- **TC-P2P-080 подтверждён**: записи отчётов попадают в общий список экспортов `GET /exports`
  (`status: completed`, `download_url` на `/static/tmp/<uuid>/<имя>`), т.е. скачиваются из раздела
  «Отчёты»/экспортов и по кнопкам на страницах работы/потока.
- **TC-P2P-081 подтверждён**: отчёт потока собрался при одной работе «На проверке» и одной «Принято»
  — ограничения «только после завершения взаимопроверки» нет.
- **Настораживает (кандидат в дефект)**: авторский `GET /my/homework-answers/{answer}/peer-review-report`
  отвечает 422 «Отчёт ещё не сформирован» ВСЕГДА — и для принятой работы 29 (итог 13.11), и для
  работы 46 через 90 с после штатной пересборки «full»-отчёта; при этом панель слушателя дёргает его
  при каждом открытии ПЗ и пишет в консоль «Server communication error». Либо авторская версия
  отчёта не генерируется вообще, либо нужен отдельный триггер — не найден.
