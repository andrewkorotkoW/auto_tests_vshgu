# Тест-кейсы: p2p / возврат на доработку

| Параметр | Значение |
|---|---|
| Область | tests/api/p2p, tests/ui/p2p (возврат работы, повторный цикл проверки) |
| Стенд | develop (см. README §13) |
| Роли | admin, reviewer, user |

Кейсы описывают целевое поведение по приоритетной версии (04 → 03, `docs/requirements/tz2026/README.md`).
Известное расхождение версий (README): возврат на доработку — 04: штатный проверяющий, повторный
цикл; 03: настройка «разрешить возврат», приостановка у всех; 01: на первом этапе не использовать.
Кейсы 054–058 написаны по приоритетной версии 04. Возврат на доработку не входит в перечень
категорий Этапа 1, отмеченных для автоматизации, — автотест не планируется.

### TC-P2P-054 Возврат работы на доработку выполняет штатный проверяющий ПЗ
- Требование: 04 §8.2 п.2
- Приоритет: high   Тип: manual   Роли: reviewer
- Предусловия: -
| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | От имени штатного проверяющего ПЗ открыть сданную работу | Работа открыта |
| 2 | Выполнить действие «Вернуть на доработку» | Работа возвращена автору, статус изменён |

### TC-P2P-055 При возврате одним проверяющим проверка приостанавливается у остальных
- Требование: 03 §9
- Приоритет: high   Тип: manual   Роли: reviewer, user
- Предусловия: По работе назначено несколько незавершённых peer-проверок
| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Один из штатных проверяющих возвращает работу на доработку | Работа возвращена |
| 2 | Проверить статус незавершённых peer-проверок у остальных проверяющих/слушателей-проверяющих | Проверки приостановлены |

### TC-P2P-056 После повторной сдачи запускается повторный цикл проверки
- Требование: 04 §8.2 п.4–5
- Приоритет: high   Тип: manual   Роли: user, reviewer
- Предусловия: Работа возвращена на доработку
| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Автор дорабатывает работу и отправляет новую версию | Новая версия сдана |
| 2 | Проверить доступность повторной оценки у тех, кто уже проверял предыдущую версию | Они снова могут открыть работу и скорректировать оценки с учётом новой версии |

### TC-P2P-057 В интерфейсе видно, что работа была доработана и доступна повторная оценка
- Требование: 04 §8.2 п.6
- Приоритет: medium   Тип: manual   Роли: reviewer
- Предусловия: Работа отправлена повторно после доработки
| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Открыть список работ на проверку | Список открыт |
| 2 | Найти доработанную работу | В интерфейсе видна пометка «доработано»/аналогичная, доступна повторная оценка |

### TC-P2P-058 Слушатель-проверяющий не может вернуть работу на доработку
- Требование: 04 §8.2 п.2, 03 §9
- Приоритет: medium   Тип: manual   Роли: user
- Предусловия: -
| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | От имени слушателя-проверяющего открыть назначенную чужую работу | Работа открыта |
| 2 | Проверить наличие действия «Вернуть на доработку» | Действие недоступно — это может выполнить только штатный проверяющий ПЗ |

### TC-P2P-059 Хранение результатов предыдущего цикла проверки после повторной сдачи
- Требование: 04 §8.2
- Приоритет: medium   Тип: manual   Роли: reviewer
- Предусловия: Ждёт ответа заказчика: вопрос №7 (05_вопросы_заказчику_16)
| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Довести работу до возврата на доработку и повторной сдачи | Новая версия сдана |
| 2 | Проверить судьбу оценок предыдущего цикла | Вариант (новая версия + старые в истории / редактирование старых / полный сброс) определяется ответом заказчика на вопрос №7 |

### TC-P2P-060 Судьба незавершённых peer-проверок в момент возврата на доработку
- Требование: 04 §8.2
- Приоритет: medium   Тип: manual   Роли: reviewer
- Предусловия: Ждёт ответа заказчика: вопрос №7 (05_вопросы_заказчику_16)
| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Вернуть работу на доработку при наличии незавершённых peer-проверок | Работа возвращена |
| 2 | Проверить состояние незавершённых проверок после возврата | Вариант (приостановка+возобновление / отмена+переназначение / без изменений) определяется ответом заказчика на вопрос №7 |

### TC-P2P-061 Сохранение прежних назначений слушателей-проверяющих после повторной сдачи
- Требование: 04 §8.2
- Приоритет: low   Тип: manual   Роли: admin
- Предусловия: Ждёт ответа заказчика: вопрос №7 (05_вопросы_заказчику_16)
| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Довести работу до повторной сдачи после доработки | Новая версия сдана |
| 2 | Проверить, сохраняются ли прежние назначения слушателей-проверяющих или выполняется новое распределение | Определяется ответом заказчика на вопрос №7 |
