# Тест-кейсы: 08. Возврат на доработку

| Параметр | Значение |
|---|---|
| Область | tests/api/p2p, tests/ui/p2p (возврат работы, повторный цикл проверки) |
| Стенд | develop (см. README §13) |
| Роли | admin, reviewer, user |

Кейсы описывают целевое поведение по приоритетной версии (04 → 03, `docs/requirements/tz2026/README.md`).
Известное расхождение версий (README): возврат на доработку — 04: штатный проверяющий, повторный
цикл; 03: настройка «разрешить возврат», приостановка у всех; 01: на первом этапе не использовать.
Кейсы 054–058 написаны по приоритетной версии 04. Возврат на доработку не входит в перечень
категорий Этапа 1, отмеченных для автоматизации, — автотест не планируется.

**17.11.2026 — живая разведка на p2p-prototype (content 192 / работа 47, демо-поток 31), полный цикл
«возврат → пересдача → повторная проверка» пройден, подтверждено с уточнениями:**
- **TC-P2P-054 подтверждён**: отдельного peer-эндпоинта возврата нет (стаб `return_for_revision` на
  `/homework/{work}/return-for-revision` был догадкой) — возврат делает ШТАТНАЯ проверка ПЗ:
  `POST /homework/{content_id}/answers/{answer_id}/examination` c `status: "sent_back"` и обязательным
  `deadline` (`api/endpoints/homework.py::examine`, в p2p.py — `return_for_revision`). После него
  `answer_status: sent_back`, `status: 7`, `sent_back_count: 1`, в `history` запись `sent_back` с
  текстом комментария. Автор в UI видит статус «Возвращено на доработку после проверки» и кнопку
  «Редактировать»; на админской странице работы кнопка «Отправить на доработку» + поле «Дата проверки до».
- **TC-P2P-055/060/068 подтверждены по сути, иначе, чем ожидалось**: на время возврата у всех
  слушателей-проверяющих `peer-submissions` отдаёт по этой работе `revision_status: "sent_back"`,
  `peer_review_allowed: false`, при этом уже завершённые проверки остаются `my_review_status:
  finalized` (привязаны к `homework_answers_history_id` старой версии). Отдельного статуса
  назначения «Приостановлена» нет — блокировка выражается флагом `peer_review_allowed=false`.
  Finalize по работе в возврате — 422 «Работа на доработке или уже принята» (как и у принятой).
- **TC-P2P-056/057/061 подтверждены**: после пересдачи автором (UI: «Редактировать» → текст →
  «Отправить» → «Отправлено на проверку») создаётся новая запись `history` (`on_review`, новый
  `homework_answers_history_id`), работа снова `status: 5/on_review`, `sent_back_count` остаётся 1.
  Назначения слушателей-проверяющих СОХРАНЯЮТСЯ (те же `reviewer_user_id` в `peer-assignments`,
  нового распределения не происходит), у них `my_review_status` сбрасывается в `null`,
  `revision_status: null`, `peer_review_allowed: true`, `review: null` в show — и черновик/финализация
  проходят заново (новый `peer_review.id` с новым `homework_answers_history_id`). В списке
  «Назначенные взаимопроверки» отдельной пометки «доработано» НЕТ — виден только новый
  `submitted_at` и сброшенный статус (TC-P2P-057 — с этим уточнением).
- **TC-P2P-059 подтверждён вариантом «новая версия + старые в истории»**: `peer-results` и блок
  «Взаимопроверка» на админской странице показывают ТОЛЬКО проверки текущей версии
  (`reviews_count` после пересдачи = 0, затем 1 после повторной проверки), старые проверки не
  удаляются (остаются в БД за старым `homework_answers_history_id`, видны в
  `peer-submissions/{id}.review` до пересдачи), но в агрегаты новой версии не входят и в UI
  отдельно не показываются — в интерфейсе их не найти (только «История изменений» текста ответа).
- **TC-P2P-058 подтверждён косвенно**: у слушателя-проверяющего нет маршрута examination в
  `/my-programs/...` (таблица `/routes`), действие доступно только через админский
  `homework.answers.examination`.
- **TC-P2P-069 (из 09) подтверждён**: `DELETE .../peer-assignments/{peer_assignment_id}` снимает
  назначение (200), у проверяющего работа пропадает из `peer-submissions`, его черновик пропадает из
  агрегатов, finalize даёт 403 «Нет peer-назначения на проверку…». Отдельного статуса «Отменена» нет —
  назначение просто удаляется.
