Разработки и ветки ещё нет (миссия `docs/missions/2026-09-30_tz2026_p2p.md`). Кейсы описывают

Спорные точки — с предусловием `Ждёт ответа заказчика: вопрос №N (05_вопросы_заказчику_16)`.

### TC-P2P-001 Тумблер «Включить взаимопроверку» выключен — ПЗ работает по стандартному сценарию
- Требование: 04 §1, §4
- Автотест: tests/api/p2p/test_pt_card_settings.py::TestPtCardSettings::test_toggle_off_keeps_standard_homework_flow
- Приоритет: high   Тип: api   Роли: admin
- Предусловия: -
| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Создать ПЗ в базе активностей без включения «Включить взаимопроверку» | ПЗ создано, настройки взаимопроверки не отображаются/недоступны |
| 2 | Назначить ПЗ в поток и пройти обычный сценарий сдачи/проверки | Работает штатный (не-P2P) сценарий проверки, как до появления взаимопроверки |

### TC-P2P-006 Блокировка тумблера «Включить взаимопроверку» после первой сданной работы
- Требование: 04 §4.1
- Приоритет: medium   Тип: manual   Роли: admin
- Предусловия: Ждёт ответа заказчика: вопрос №14 (05_вопросы_заказчику_16) — предложенный вариант: после начала взаимопроверки настройку нельзя выключить, можно только завершить/отменить конкретный запуск в потоке с сохранением истории
| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Включить взаимопроверку у ПЗ, назначить в поток, дождаться первой сданной работы, участвующей во взаимопроверке | Работа сдана |
| 2 | Попытаться выключить тумблер «Включить взаимопроверку» в карточке ПЗ | По варианту из вопроса №14 — тумблер заблокирован; администратор может только завершить/отменить запуск P2P в потоке |
