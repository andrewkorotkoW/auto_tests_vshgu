# Факты по мобильной вёрстке портала (Pixel 7, develop)

Технический конспект для написания мобильных веток в page objects — не документация
пользователя. Снято на `--env develop`, `HEADLESS=1`, профиль контекста `--mobile`
(Playwright `devices["Pixel 7"]`, viewport 412×839, см. `conftest.py::MOBILE_DEVICE`),
06.10.2026. Скриншоты сделаны временным сценарием (не сохранён в репозитории, см.
`docs/reports/2026-10-06_mobile_mission.md`), только реальные наблюдения, без домыслов.

## 1. Вход (`/auth/main`)

- Форма идентична desktop по DOM/селекторам (`input[name="email_or_login"]`,
  `input[name="password"]`, `button:has-text("Войти")`) — `LoginPage.login()` работает
  без изменений, мобильная ветка не нужна.
- Вёрстка уже одноколоночная и адаптивная: лого «Президентская академия» сверху,
  белая карточка формы на синем фоне, чекбокс «Запомнить меня», ссылка «Не помню
  пароль», кнопка «Техподдержка» внизу (плавающая, с иконкой шестерёнки).

## 2. Список программ (`/education`, куда редиректит `/programs` и переход по кнопке
   «Мое обучение»)

- Шапка: заголовок раздела слева, гамбургер-меню (≡) справа — **не** кнопка с ФИО/
  аватаркой, как на desktop.
- **Нижняя панель вкладок (bottom bar)**, 4 пункта, подтверждён DOM:
  `<a class="bottom-bar__link" role="link">` — «Мое обучение», «База знаний»,
  «Техподдержка», «Профиль». «Уведомления» в нижней панели **нет** — туда попадают
  только через прямой переход на `/portal-notifications` (desktop-пункт сайдбара
  `SIDEBAR_BUTTONS["Уведомления"]` в мобильной нижней панели не представлен).
- Карточка программы — крупный синий блок (не похожий на desktop-таблицу/список):
  название, рейтинг (звезда), ссылка «О программе», город, даты, кнопка
  «Перейти к программе» на всю ширину под карточкой.
- **Важно для page objects**: несмотря на визуально другую карточку, DOM-анкор
  `a.program-card__link` с точным текстом названия программы (на который опирается
  `PracticalTaskPage.program_title()`/`open_program()`) **сохраняется и кликабелен**
  без изменений — мобильная ветка для открытия программы по имени не потребовалась.
- Блок «Индивидуальное обучение» наверху — та же синяя карточка-баннер, что и на
  desktop, без видимых отличий кроме ширины.

## 3. Активити (тест/опрос, плеер `/testing/player`)

- Вступительный слайд («Вступительный слайд» + кнопка «Начать») рендерится в
  компактной белой карточке на светлом градиентном фоне — минималистичнее desktop,
  но те же селекторы (`get_by_role("button", name="Начать")`).
- **Замечена гонка данных**: сразу после клика «Начать» страница вопроса иногда
  отрисовывает чистую вёрстку (заголовок группы, таймер «Осталось MM:SS», кнопка
  «Ответить») **с плейсхолдерами вместо реального текста** — «Заголовок вопроса…»
  и «Выберите ответ..» для обоих вариантов — пока не подъехали реальные данные
  вопроса. `ConstructorPlayerPage.answer_question(text)` (поиск точного текста
  ответа) в этот момент не находит элемент и падает по таймауту. Не проверено,
  воспроизводится ли то же на desktop при аналогичной задержке сети — похоже на
  общую гонку рендера, а не мобильный баг, но зафиксировано как факт, не как вывод.
  Для мобильных веток активити (следующая задача) потребуется дождаться реального
  текста вопроса/ответа отдельным ожиданием, а не полагаться на
  `wait_for_load_state("networkidle")`.
- Заголовок теста обрезается без переноса/троеточия на узком экране (ширина карточки
  меньше длины названия) — визуальный дефект по сравнению с desktop, где заголовок
  переносится.

## 4. Карточка программы (`/education/program/{uuid}/module/{id}`)

- Шапка — «← Назад» вместо заголовка страницы, гамбургер справа.
- Под шапкой — иконки-кнопки «Материалы» и «Участники» (desktop показывает то же,
  но в виде горизонтальных вкладок/кнопок с текстом, не иконок-колонок).
- Список модуля — три карточки-аккордеона с шевроном `>`: «Расписание»,
  «Курсы и тесты», «Игровая сессия» — на desktop это вкладки в одну строку, на
  мобильном — вертикальный список кликабельных карточек.
- Сертификат после завершения активности: в рамках разведки создать и подтвердить
  полный цикл «пройти единственный тест → получить сертификат» не удалось —
  `CertificatesEndpoint.assign_template(template_type="activity", content_ids=[test_content_id])`
  отдаёт `422 content_ids.0 некорректно` (сервер в этом месте ждёт другой тип
  content_id, видимо `content_id` потока/стрима, как в
  `tests/api/certificates/assign/program/test_assign_template.py`, а не activity
  напрямую) — это не мобильный дефект, это особенность API сертификатов, с которой
  нужно разобраться отдельно. Карточка программы после попытки прохождения
  активити внешне не отличалась от карточки до прохождения (тот же набор из
  3 карточек-аккордеонов) — видимого индикатора прогресса/сертификата в этом
  прогоне не появилось, но ввиду сбоя назначения сертификата это не окончательный
  факт об отсутствии такого индикатора в принципе.

## 5. Профиль

- **Нет отдельного URL**: клик по нижней вкладке «Профиль» (`a.bottom-bar__link`)
  **не меняет `page.url`** — это переключение внутреннего состояния SPA (вероятно,
  вкладка/panel index), а не навигация роутера. Подтверждено дважды: URL до и после
  клика идентичен в обоих случаях.
- Клик по вкладке «Профиль» работает **только со страницы списка программ
  (`/education` корень)** — тот же клик с вложенного маршрута карточки программы
  (`/education/program/.../module/...`) оказался no-op: DOM не менялся, URL не
  менялся, подтверждено повторным прогоном.
- После успешного клика с `/education` появляются три вкладки верхнего уровня:
  «Профиль» (активна), «Мои сертификаты», «Документы о квалификации» — то есть
  структура похожа на desktop (разделы профиля), но **содержимое вкладки
  «Профиль» так и не отрисовалось — завис бесконечный спиннер загрузки**
  (`.v-progress-circular`), воспроизведено в двух последовательных прогонах с
  ожиданием до ~17 секунд после клика. Похоже на реальный дефект мобильной вёрстки
  (или API-запрос профиля, специфичный для вкладки, не завершается/ошибается), а
  не на недостаточное ожидание — кандидат в дефекты для разбора в следующей задаче.
- `UserSidebarPage.user_name()` (локатор `.user-menu`) на мобильном **не находит
  элемент вовсе** (таймаут 30 с на `inner_text()`, что означает отсутствие в DOM, а
  не просто CSS-скрытие — `inner_text()` не требует видимости, только attach) —
  подтверждено прогоном `tests/ui/users/test_user_login_navigation.py::test_login_with_user_credentials`
  с `--mobile`. Эта проверка ФИО в шапке для мобильных веток непригодна как есть.

## 6. Уведомления (`/portal-notifications`)

- Открывается напрямую по URL без проблем (как и `UserSidebarPage.open()` ожидает).
- Шапка «← Назад» (не заголовок раздела), кнопка «Отметить все как прочитанные» на
  всю ширину под шапкой, дальше пустой список (свежесозданный пользователь без
  уведомлений — ожидаемо).
- Нижняя панель вкладок видна и здесь, тот же набор из 4 пунктов.

## Итог для мобильных веток (часть 4 миссии)

Для сценария «вход → список программ» (единственный обязательный в этой задаче)
дополнительные мобильные ветки в page objects **не потребовались**:
`LoginPage.login()` и `PracticalTaskPage.open_programs_list()`/`program_title()`/
`open_program()` работают на Pixel 7 без изменений — те же DOM-селекторы, разница
только визуальная (стилизация карточки, нижняя панель вместо сайдбара). Добавлена
фикстура `is_mobile` (`conftest.py`) для будущих веток.

Для следующей задачи (dwight, экраны 3–6) понадобятся реальные мобильные ветки:
- активити — дождаться реального текста вопроса/ответа отдельным ожиданием (не
  полагаться на `networkidle`), см. п. 3;
- профиль — альтернативный способ проверки «вход успешен» (без `.user-menu`),
  переход на вкладку «Профиль» только с `/education` (не с вложенных маршрутов), и
  разбор зависающего спиннера на содержимом вкладки, см. п. 5;
- сертификат — сначала разобраться с форматом `content_ids` для
  `CertificatesEndpoint.assign_template` вне мобильного контекста, см. п. 4.
