Записано 05.10.2026. Админка хелпдеска — единственная крупная область с нулевым покрытием
(`tests/product_map.yml`: `int_helpdesk ... tests: []`; `qa_analysis/cases/COVERAGE_2026-09-22`:
`helpdesk / tickets / chats — 8 routes, 0 covered`). Пользовательская часть тикетов
(`/api/v1/tickets/*`, `docs/test_cases/tickets.md`, `tests/api/tickets`, `tests/ui/tickets/user`) уже покрыта —
её не переделывать, только ссылаться.

## Исходные данные

- Стенд хелпдеска (единственный, рабочий dev): `https://helpdesk-develop.d2.devspark.ru` — корень редиректит на
  `/admin/ticket`, авторизация общая с порталом develop (та же сессия/учётка админа, что и
  `--env develop` → `admin_session`/`admin_page`). Доступ есть у ролей Администратор, Администратор организации,
  Поддержка, Поддержка (Helpdesk). Разделы по боковому меню: Тикеты, Группы (`/admin/group`), Пользователи,
  Заявители, Шаблоны, Дашборды, Справочники.
- Кейсы-источник: Test IT, проект «ВШГУ v.2» (globalId 9466), раздел Helpdesk
  (`32cce4ea-08ba-43b9-bcbb-b18374367cba`). Выгрузка со всеми шагами лежит рядом:
  `docs/plans/helpdesk_testit_v2_export.md` (+ `.json`) — 24 элемента: 21 test case + 3 shared steps, подразделы
  Тикеты (1), Группы (5), Пользователи (4), Карточка пользователя (2), Заявители (6), Шаблоны (5), Дашборды (1);
  подразделы Справочники/* (7 штук) и «Автоматическое создание группы по тенанту» — пустые.
- Цель в Test IT: проект «ВШГУ v.3» (globalId 9712; его GUID уже в `.env` как `TESTIT_PROJECT_ID`). Раздела
  Helpdesk там пока нет — создать с той же структурой подразделов.
- Цель в test_hub: проект `VSHGU` (импорт `POST /api/projects/VSHGU/testcases/import` читает
  `docs/test_cases/**/*.md`, кроме `TEMPLATE.md`; upsert по `TC-ID`, ручные правки (`source=manual`) не затирает).

## Правила (обязательны)

- Только `--env develop` и `helpdesk-develop` (`HEADLESS=1`). Stage, prod, k8s не трогать.
- Учётки и токены только из `.env` через `config/environments.py`; значения `.env` в код, логи, md и коммиты не
  писать. Test IT — только через `tools/test_cases/testit_sync.py` (`TESTIT_URL/TESTIT_TOKEN/TESTIT_PROJECT_ID`);
  сначала `--dry-run`, `--apply` — отдельной задачей в конце.
- Единый источник кейсов — markdown по `docs/test_cases/TEMPLATE.md`: `docs/test_cases/helpdesk/<область>.md`
  (нумерация `TC-HELPDESK-<ОБЛАСТЬ>-NNN`, например `TC-HELPDESK-GROUPS-001`). Из этого md и в Test IT
  (`testit_sync.py --docs-dir docs/test_cases/helpdesk --parent-section Helpdesk`), и в test_hub (импорт).
- Каждый кейс из выгрузки v.2 перед переносом **проверить руками на helpdesk-develop** (Playwright под админом):
  актуализировать названия полей/кнопок/URL, обязательные поля, ожидаемые результаты. Шаги, которых на стенде
  больше нет, — не переносить, а перечислить в отчёте задачи как «устарело». Shared steps (3 шт.) разворачивать
  в предусловия/первые шаги кейсов, отдельной сущностью не заводить.
- Структура кода как в проекте: `api/endpoints/helpdesk.py`, тесты в `tests/api/helpdesk/` и
  `tests/ui/helpdesk/admin/`, фикстуры в `conftest.py` рядом, генерация данных в `api/helpers/data_generator.py`
  (префикс `Автотест_`), маркеры `api`/`ui`, allure feature/story/title на русском, `expect_status`.
- Каждый тест независим: сам создаёт данные и удаляет их в teardown даже при падении; хардкодов id нет.
- Запускать только свои тесты (`pytest tests/api/helpdesk tests/ui/helpdesk --env develop -q`), не полный прогон.
- Поведение не по ожиданию — не подгонять assert: `xfail(strict=False)` с причиной + кандидат в дефекты в отчёте.
- Группы: не трогать существующие системные группы и их почтовые настройки (IMAP/SMTP); создавать только свои
  `Автотест_*` с заведомо фиктивными почтовыми реквизитами и удалять. Заявители/пользователи — только тестовые
  (`auto_test_*`), роли назначать только им.

## Часть 1. Разведка (одна задача, без тестов)

1. Войти на helpdesk-develop под админом develop (Playwright, та же сессия, что `admin_page`), пройти все разделы
   меню, зафиксировать URL каждого раздела и, перехватив запросы, реальные API-маршруты хелпдеска (база, префикс,
   формат ответов, CSRF/заголовки) — в `docs/helpdesk_recon.md`. Отметить, что из 7 пустых подразделов
   «Справочники» реально есть на стенде.
2. По выгрузке v.2 составить таблицу «кейс → актуален / требует правки / устарел» с пометками, что изменилось.

## Часть 2. Кейсы (markdown → Test IT v.3 → test_hub)

3. Написать `docs/test_cases/helpdesk/{tickets,groups,users,applicants,templates,dashboards}.md` по шаблону:
   все актуальные кейсы v.2 (с правками по разведке) + недостающие базовые для Справочников, если они есть на
   стенде (просмотр списка, создание/редактирование/удаление записи — по одному кейсу на справочник).
   У кейсов, которые будут автоматизированы, — строка `- Автотест: <nodeid>`; остальные ручные.
4. `testit_sync.py --dry-run --docs-dir docs/test_cases/helpdesk --parent-section Helpdesk` → проверить план
   (секция Helpdesk с подразделами внутри «ВШГУ v.3»), затем `--apply`; id записать в md (`- Test IT: <id>`).
5. Импорт в test_hub: `POST /api/projects/VSHGU/testcases/import` (test_hub на `http://127.0.0.1:8700`, роль qa) —
   убедиться, что кейсы появились в разделах `helpdesk/*` без дублей с `api/tickets`/`ui/tickets`.

## Часть 3. Автотесты (по результатам разведки)

6. API (`tests/api/helpdesk/`): CRUD групп (создание с фиктивными IMAP/SMTP, просмотр, редактирование, удаление),
   CRUD шаблонов, поиск пользователя и заявителя, добавление заявителя, назначение роли пользователю, список
   тикетов; негатив — обязательные поля (422), чужой/несуществующий id (403/404).
7. UI (`tests/ui/helpdesk/admin/`, Playwright): переход по разделам меню (Тикеты, Группы, Пользователи, Заявители,
   Шаблоны, Дашборды) с проверкой URL и заголовка; создание и удаление группы через форму; создание шаблона;
   карточка пользователя — назначение роли; переход из карточки заявителя в карточку пользователя ВШГУ
   (вкладка «Обучение»). Page object'ы — `ui/pages/helpdesk_*.py`.
8. `tests/product_map.yml`: заполнить `int_helpdesk.tests` новыми nodeid.
