# Миссия: «Чат с ИИ в курсах» — автотесты по ПМИ, кейсы в Test IT, отдельная область `ai_chat`

Записано 07.10.2026 по решению владельца: функционал «Чат с ИИ в курсах» (ПМИ «Чат с ИИ_курсы_ПМИ_v2»)
покрыть автотестами как отдельную область проекта — по образцу CAS (`tests/api/cas`, `tests/ui/cas`,
`docs/test_cases/cas.md`, узел `int_cas` в `tests/product_map.yml`), а кейсы залить в Test IT «ВШГУ v.3».
Шаги ПМИ — `docs/plans/ai_chat_pmi_scenario.md` (33 шага + 4 исключённых). Проверки через pgAdmin
(блок «Логирование») **исключены** — решение владельца.

## Исходные данные

- Стенд: только `--env develop` (`https://portal-develop.d2.devspark.ru`), `HEADLESS=1`. Функционал на develop
  есть: у активити поле `is_llm_chat_enabled`, у `GET /activities` элементы с `permissions` содержат
  `content.llm_chat` (admin). Prod, stage, k8s не трогать.
- Контракт API (снят 07.10 перехватом запросов фронта, активити 7455 на develop, затем удалена):
  - `GET /content/{id}/llm-chat` → `{"data": null}`, пока чат не настраивался; после настройки — объект
    `{id, llm_knowledge_uuid, is_enabled, knowledge: {llm_knowledge_uuid, user_id, knowledge_name (= имя активити),
    meta: {files: {<file_uuid>: {llm_storage_uuid, status}}}, files: {<storage_uuid>: <имя файла>}, status, user},
    questions_count, answers_count, created_at, updated_at}`.
  - `POST /upload/llm_knowledge_files` (multipart, поле файла как у `TincanEndpoint.upload_*`) →
    `{"data":[{"uuid": <storage_uuid>, "attributes": {name, type, size, url, ...}}]}`.
  - `POST /content/{id}/llm-chat` с телом `{"files": [<storage_uuid>, ...], "is_enabled": 1}` → 201, знание
    создано, статусы файлов `pending`; через ~1 мин файл получает `completed` | `short_context` (мало текста) |
    `empty_context` (нет текста, скан) ; `knowledge.status` → `completed`, если все файлы `completed`,
    иначе `failed` (один непригодный файл валит весь контекст — владелец: так и должно быть).
  - `PATCH /content/{id}/llm-chat` — выключение переключателя (пустое тело) → `{"data":{"status":"success"}}`,
    `is_llm_chat_enabled` → false. Удаление файла корзиной — по ручному прогону 29.09 `PATCH /llm-knowledge/{uuid}/files`;
    точное тело снять перехватом в разведке.
  - `GET /content/{id}/llm-chat/export` → `{"data":{"status":"success"}}` (файл формируется асинхронно, скачивается
    на внешке — содержимое файла автотестом не проверяется).
  - Список/фильтр: `GET /activities?...&filters[llm_chat]=1` возвращает 200 — проверить в разведке, какое имя фильтра
    реально шлёт фронт по галочке «Курсы с чатом ИИ» (неизвестные фильтры API молча игнорирует).
  - Слушатель: чат в плеере (`button.player-chat-toggle`, подпись «ИИ-помощник по курсу», подсказка «Обсудить
    материалы курса с ИИ»); запросы вопроса/ответа/оценки/истории снять в разведке (во время ответа поле ввода
    заблокировано, подпись «ИИ помощник печатает…»; оценка — блок со звёздами в самом чате после первого ответа).
  - Статистика: `Статистика обучения → Курсы → <курс> → «Оценки и отзывы»` (`/learning-statistics/courses/{id}/feedback`).
- Факты стенда, подтверждённые владельцем 29.09 (тесты проверяют их, а не текст ПМИ): флаг чата сохраняется
  только вместе с первым файлом; значок «Чат с ИИ» в таблице привязан к переключателю, а не к наличию документов;
  текст отказа не по теме и подсказки отличаются от ПМИ. Единственное открытое расхождение — D2: у файла без текста
  нет подписи «В документах не найден текст» (есть общая «Не удалось обработать часть файлов») → `xfail(strict=False)`
  со ссылкой на `qa_analysis/cases/VSHGU2-2375_AI_chat_PMI_2026-09-29/report.md`.
- Тестовые документы уже лежат в `test_data/llm/`: `soups.docx` (~2,4 тыс. слов, обрабатывается → `completed`),
  `soups.txt`, `soups.pdf` (текст того же документа), `pea_soup.md` (6 КБ), `scan_images_only.pdf` (только картинки
  → `empty_context`). Неподдерживаемый формат — `test_data/practical_task_additional_document.xlsx`.
  Короткий файл для `short_context` — `test_data/practical_task_main_document.docx` (981 байт).
- Вопросы к ИИ: по контексту — про супы из документов («Из чего варят гороховый суп?»); не по теме — любой вопрос
  не про еду («Какая столица Австралии?»); про тест — «Какой правильный ответ в тесте?», «Помоги решить тест».

## Правила (обязательны)

- Учётки и токены только из `.env` через `config/environments.py`; значения `.env` в код, md, логи и коммиты не писать.
- Структура как у области CAS: `api/endpoints/llm_chat.py` (класс `LlmChatEndpoint`: `get`, `upload_files`, `setup`,
  `disable`, `remove_file`, `export`, `wait_processed(timeout=180)`), фикстуры `llm_chat_endpoint`, `tincan_with_ai_chat`
  (создать Tincan → загрузить `soups.docx` → дождаться `completed`; teardown удаляет активити) в `tests/api/ai_chat/conftest.py`
  и `tests/ui/ai_chat/conftest.py` (общие — в корневой `conftest.py`, рядом с `created_tincan`), тесты в `tests/api/ai_chat/`,
  `tests/ui/ai_chat/admin/`, `tests/ui/ai_chat/user/`, page object'ы `ui/pages/admin_activity_ai_chat_page.py`
  (вкладка «Чат с ИИ» в карточке активити `/admin/activities/{id}?i=1`) и `ui/pages/player_ai_chat_page.py` (чат в плеере).
  Маркер `ai_chat` в `pytest.ini` (`--strict-markers`), `@allure.feature("Чат с ИИ в курсах")`, story/title на русском,
  `expect_status`, шаги `with allure.step(...)` — по ним генерируются кейсы.
- Каждый тест независим: сам создаёт активити/пользователей через API и удаляет в teardown даже при падении
  (`tincan_endpoint.delete`, `users_endpoint.delete`); хардкодов id нет; имена с префиксом `Автотест_`.
- Ответы ИИ недетерминированы и небыстры: ждать ответ до 120 с; проверять наличие ответа, дату/время, рост счётчиков
  `questions_count`/`answers_count`, сохранение истории — **точный текст ответа не фиксировать**. Для вопросов не по теме
  и про тест — только «ответ получен и записан в историю»; смысловая проверка отказа остаётся ручным кейсом.
- Обработка контекста — ждать статус опросом `GET /content/{id}/llm-chat` до 180 с, не `sleep` с магическим числом.
- Поведение не по ожиданию — не подгонять assert: `xfail(strict=False)` с причиной + кандидат в дефекты в отчёте.
- Запускать только свои тесты: `pytest tests/api/ai_chat tests/ui/ai_chat --env develop -q`. Полный прогон не нужен.
- Чужие активити на develop (например «Проверка_25.09», «QA Tincan test», «Тест_ИИ_в_курсах» из ПМИ) не трогать —
  все проверки на своих, созданных тестом.
- Test IT — только через `tools/test_cases/testit_sync.py` (`TESTIT_URL/TESTIT_TOKEN/TESTIT_PROJECT_ID` из `.env`);
  сначала `--dry-run`, `--apply` — отдельной последней задачей.
- Коммиты без трейлера `Co-Authored-By`.

## Часть 1. Разведка (одна задача, без тестов)

1. Под админом develop (Playwright, перехват запросов): создать Tincan через API, на вкладке «Чат с ИИ» включить
   переключатель, загрузить `soups.docx` и `scan_images_only.pdf`, удалить файл корзиной, выключить переключатель;
   записать в `docs/ai_chat_recon.md` точные запросы (метод, путь, тело, ответ) для удаления файла и имя фильтра
   «Курсы с чатом ИИ»; снять селекторы вкладки, переключателя, зоны загрузки (`expect_file_chooser`, скрытого
   `input[type=file]` нет), списка файлов, корзины, блока «История ИИ-чата», значка в таблице и фильтра.
2. Под слушателем: назначить активити с готовым контекстом в поток (как в `tests/ui/courses/tincan`) и в индивидуальное
   обучение (`assign_activities`), открыть плеер, снять запросы вопроса/ответа/истории/оценки и селекторы чата
   (кнопка, поле ввода, сообщения, даты, звёзды, комментарий). Зафиксировать среднее время ответа.
3. Таблица «шаг ПМИ → автотест (api/ui) / ручной / исключён» в `docs/ai_chat_recon.md`.

## Часть 2. Автотесты

4. API (`tests/api/ai_chat/`): `GET llm-chat` пустой у новой активити; настройка с `soups.docx` → 201, статус файла
   доходит до `completed`, `knowledge.status == completed`, `is_llm_chat_enabled == true` в `GET /content/{id}` и в
   строке `GET /activities`; каждый формат (txt, pdf, md — параметризованно) → `completed`; `scan_images_only.pdf` →
   `empty_context` и `knowledge.status == failed`; короткий docx → `short_context`; удаление файла; выключение
   (`PATCH`) → `is_llm_chat_enabled == false`; фильтр «Курсы с чатом ИИ» возвращает только активити с чатом;
   `export` → 200 `status: success`; счётчики вопросов/ответов после вопроса слушателя через API (если запрос
   вопроса снят в разведке — иначе этот кейс UI).
5. UI админ (`tests/ui/ai_chat/admin/`): шаги 4–17 и 19–21 сценария — значок в таблице до/после настройки; вкладка,
   подсказка, переключатель → блок «Контекст обсуждения»; загрузка docx → файл в списке и блок «История ИИ-чата»;
   загрузка txt/pdf/md; скан-pdf → подпись (xfail D2); перетаскивание xlsx → «Данный формат не поддерживается»
   (через `page.dispatch_event('drop', {dataTransfer})`); корзина → файл удалён; удалить все документы → подпись
   «Файлы контекста пока не загружены…», значок остаётся (факт); фильтр «Курсы с чатом ИИ»; счётчики и «Скачать историю».
   Повтор для Scorm — параметризацией `tincan|scorm`, если `created_tincan`/генератор умеют Scorm, иначе отметить в отчёте.
6. UI слушатель (`tests/ui/ai_chat/user/`): шаги 23–33 — кнопка чата и подсказка в плеере курса из потока; вопрос по
   контексту → блокировка поля на время ответа, ответ с датой/временем; вопрос не по теме и про тест → ответы записаны;
   оценка звёздами + комментарий → отправлена; повторный вход → история сохранена; то же для индивидуального
   обучения (один сквозной тест); курс с выключенным чатом и курс с удалёнными документами → кнопки нет
   (`to_be_hidden`). Видео в Allure у сквозных тестов, как у мобильных.
7. `tests/product_map.yml`: узел `adm_ai_chat` (зона adm, label «Чат с ИИ», свободные координаты рядом с
   `adm_activities`, `target: ext_course`) с nodeid новых тестов; связь `{from: adm_ai_chat, to: ext_course}`.

## Часть 3. Кейсы (markdown → Test IT → test_hub)

8. `python tools/test_cases/generate.py --area ai_chat` → черновик `docs/test_cases/ai_chat.md`; довести до читаемого
   вида по `TEMPLATE.md`: заголовок `# Тест-кейсы: Чат с ИИ в курсах`, нумерация `TC-AI_CHAT-NNN`, шаги словами по
   ПМИ, у автоматизированных — `- Автотест: <nodeid>`; ручными кейсами (без автотеста) добавить: смысловая проверка
   отказа не по теме и про тест (шаги 26–28), содержимое файла истории (шаг 21), подсказка при наведении (шаг 7),
   «Оценки и отзывы» в статистике (шаг 22), если не автоматизирован. Шаги pgAdmin в кейсы не включать.
9. `python tools/test_cases/testit_sync.py --dry-run` (область `ai_chat` ляжет секцией «Чат с ИИ в курсах» в «ВШГУ v.3») →
   проверить план → `--apply`, id записать в md (`- Test IT: <id>`). Отдельная последняя задача.
10. Импорт в test_hub: `POST http://127.0.0.1:8700/api/projects/VSHGU/testcases/import` (роль qa) — убедиться, что
    раздел `ai_chat` появился без дублей.
