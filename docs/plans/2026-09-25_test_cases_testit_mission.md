# Миссия: тест-кейсы по функционалу ВШГУ и передача в Test IT

Записано 25.09.2026. Цель: у каждого автотеста есть тест-кейс в человеческом виде, кейсы лежат
в репозитории и заливаются в Test IT; для новых фич порядок — сначала кейсы, потом автотесты.

## Правила

- Стенды не трогать: миссия про документы и скрипт синхронизации, ни один тест не запускать
  на stage/prod. Для проверки скрипта — сухой режим (`--dry-run`), без сети.
- Доступ к Test IT только через `.env`: `TESTIT_URL`, `TESTIT_TOKEN` (PrivateToken),
  `TESTIT_PROJECT_ID`. Значений в код, логи, README и коммиты не писать. Пока переменных нет —
  скрипт работает в сухом режиме и пишет, чего не хватает.
- Кейсы на русском, по шаблону ниже, один файл на область — как папки `tests/api/<area>` и
  `tests/ui/<area>`.

## Часть 1. Формат кейсов и генератор из allure-разметки

1. Формат: `docs/test_cases/<area>.md`, в каждом файле таблица-шапка (область, стенд, роли) и кейсы:
   ```
   ### TC-<AREA>-<NNN> <Название>
   - Автотест: tests/api/notifications/test_notifications_crud_api.py::TestNotificationsCrudApi::test_create_notification
   - Приоритет: high|medium|low   Тип: api|ui|e2e   Роли: admin, user
   - Предусловия: …
   | Шаг | Действие | Ожидаемый результат |
   |---|---|---|
   | 1 | … | … |
   ```
2. Генератор `tools/test_cases/generate.py`: собирает тесты через `pytest --collect-only`
   (без запуска), читает `@allure.feature/story/title/severity`, маркеры и докстринги, шаги —
   из `with allure.step("…")` статически (ast), пишет черновики кейсов по областям. Существующие
   вручную правленные кейсы не перезаписывает: у каждого кейса поле `Автотест:` — ключ; новые
   тесты добавляются, для изменённых шагов ставится пометка `<!-- обновить -->`.
3. Прогнать генератор по всему `tests/` — получить черновики для всех областей (сейчас 261 тест),
   затем вручную довести до читаемого вида кейсы трёх областей как образец: `notifications`,
   `tickets`, `learning_statistics` (ожидаемые результаты словами, а не именами локаторов).

## Часть 2. Синхронизация с Test IT

1. `tools/test_cases/testit_sync.py`: читает `docs/test_cases/*.md`, для каждой области создаёт
   секцию в проекте Test IT, для каждого кейса — work item типа «Test case» с шагами, ожидаемыми
   результатами, приоритетом, тегами (area, api/ui, роли) и атрибутом/тегом с путём автотеста.
   Повторный запуск обновляет существующие (поиск по названию + тегу автотеста), не плодит дубли.
   API: Test IT public API v2 (`/api/v2/workItems`, `/api/v2/projects/{id}/sections`),
   заголовок `Authorization: PrivateToken <TESTIT_TOKEN>`; `requests`, без новых зависимостей.
2. Режимы: `--dry-run` (по умолчанию, если нет `.env`-переменных): печатает, что создал бы/обновил,
   и пишет `workspace/testit_export.json` с телами запросов; `--apply` — реальная заливка;
   `--area notifications` — только одна область.
3. После заливки id work item записывается обратно в кейс (`- Test IT: 12345`), чтобы автотест
   можно было привязать: в `conftest.py` добавить хук, который по `Автотест:` → `Test IT:` из
   кейсов ставит allure-label `testit_id` (для отчёта) — без обязательной установки адаптера.
   Отдельно описать в README, как включить официальный `testit-adapter-pytest` (опционально,
   не добавлять в requirements по умолчанию).

## Часть 3. Процесс «кейсы → автотесты»

- README, раздел «Тест-кейсы и Test IT»: где лежат кейсы, как сгенерировать черновик, как
  заливать, правило для новых фич: сначала кейсы в `docs/test_cases/`, ревью владельца, потом
  автотесты с ссылкой на TC-id в `@allure.title` или label.
- Шаблон кейса `docs/test_cases/TEMPLATE.md`.

## Тесты

- `tests/tools/test_test_cases_generate.py`: генератор на маленьком фикстурном дереве тестов
  (2–3 файла с allure-шагами) — правильные TC-id, шаги, не перезаписывает ручные правки.
- `tests/tools/test_testit_sync.py`: парсер md → work item payload; dry-run без сети; `--apply`
  с замоканным `requests` (создание, обновление, отсутствие дублей).

## Сдача

- Черновики кейсов по всем областям + три доведённые области.
- `testit_sync.py --dry-run` отрабатывает на всех кейсах, `workspace/testit_export.json` приложен.
- README и шаблон. Реальную заливку (`--apply`) делает владелец после проверки экспорта.
