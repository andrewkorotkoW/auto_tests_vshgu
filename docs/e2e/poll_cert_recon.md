# Разведка: опрос в потоке + неавторизованный доступ, сертификат слушателя (develop, 15.10.2026)

Для черновиков TC-E2E-038/039 из `docs/test_cases/e2e.md`. k8s выведен из эксплуатации
(владелец, 15.10.2026) — разведка и дальнейшая автоматизация переносятся на develop
(стенд подтверждён живым с 14.10 вечера). Скрипты: `scripts/_recon_poll_stream.py`,
`scripts/_recon_certificate_listener.py` (не часть прогона, оставлены для повторного
использования).

## Опрос в потоке + неавторизованная попытка (TC-E2E-038) — разведано полностью

- **Создание и назначение в поток**: тот же API-рецепт, что уже есть в
  `tests/api/e2e/test_e2e_content_to_module.py::test_e2e_poll_to_module` — `PollsEndpoint.create`
  (обложка через `TincanEndpoint.upload_cover`) → вопросы `create_question` → назначение в
  модуль `AssignmentsEndpoint.assign_content_to_module`.
- **UI слушателя**: тот же путь, что у теста в потоке
  (`tests/ui/tests/stream/test_user_test_stream_flow.py`) — логин → онбординг внутри
  программы (`UserSidebarPage.pass_onboarding()`) → вкладка «Курсы и тесты» → карточка по
  имени (`name_client` или `name`). Только что назначенный контент иногда не виден сразу —
  один reload+retry обычно хватает (индексация, тот же эффект, что уже задокументирован для
  тестов).
- **Запуск плеера**: клик «Начать» открывает плеер в НОВОЙ вкладке (как у инд. опроса,
  `tests/ui/polls/individual/test_poll_flow.py`), URL вида
  `/testing/player/{content_id}/{assignment_uuid}`.
- **Неавторизованный доступ — ключевой результат**: та же ссылка плеера в браузерном
  контексте без куки сессии → редирект на
  `/auth/main?uri-callback=%2Ftesting%2Fplayer%2F{content_id}%2F{uuid}` (обычная форма
  логина с колбэком). В отличие от АОС (`tests/ui/aos/user/test_aos_public_link.py`,
  `AosEndpoint.public_link` — отдельный backend-эндпоинт публичной ссылки), у опроса в
  потоке анонимного/публичного доступа к плееру НЕТ — это ожидаемое поведение, не дефект:
  публичная ссылка подтверждена как отдельная фича именно АОС, опрос её не предоставляет.
- Прогона теста на самом опросе (ответы на вопросы) не делал — сценарий такой же, как уже
  покрыт в `test_ui_poll_flow` (инд. трек), автоматизация может переиспользовать те же шаги
  взаимодействия с плеером.

**В кейс (TC-E2E-038) можно класть как есть**: API — программа → поток → модуль, назначить
слушателя на поток, создать опрос с вопросами, назначить в модуль; UI — слушатель находит
и проходит опрос на вкладке «Курсы и тесты» (как `test_user_test_stream_flow`/`test_ui_poll_flow`
вместе); скопировать URL плеера; тот же URL без сессии → редирект на `/auth` с
`uri-callback` — это ожидаемое поведение, не xfail/баг.

## Сертификат слушателя программы (TC-E2E-039) — разведано и воспроизведено полностью

**Ключевая ошибка первых раундов**: `AssignmentsEndpoint.change_state(state=CONTENT_STATE_PASSED)`
— служебный короткий путь, которым пользуется `test_courses_table_progress.py` ТОЛЬКО для
проверки счётчиков дашборда. Он не эмулирует реальное прохождение и сертификат по нему не
начисляется (4 попытки подряд, 0 результат, подробности ниже). Как подсказал владелец:
**нужно реально пройти активити через UI-плеер** — тогда сертификат начисляется быстро
(подтверждено: уведомление пришло уже через 20с ожидания).

**Рабочий рецепт (`scripts/_recon_cert_stream_real_pass.py`, подтверждён живым прогоном
15.10.2026)**:
1. Программа → поток → модуль → **тест** (не курс Tincan — тот путь перепробован и
   заблокирован известным дефектом стенда, см. ниже; не опрос — у опроса нет понятия
   «правильный ответ», значит нет и признака «пройдено на столько-то процентов»).
   `generate_test_payload(cover_uuid=..., completion_percent=0)` — бэкенд сам добавляет к
   новому тесту вопрос-заглушку («Заголовок вопроса...», без явно правильного варианта),
   наш вопрос (`create_question`, с «Правильный ответ»/«Неправильный ответ» по умолчанию) —
   второй. `completion_percent=0`, чтобы не зависеть от результата по заглушке.
2. Шаблон сертификата `template_type="program_stream"`, `assign_template(id, [stream["attributes"]["content_id"]])`
   (ответ `{"result": true}`) — как и раньше, назначается на content_id ПОТОКА, не теста и не программы.
3. Пользователь назначен на поток (`assignments_endpoint.assign`), НЕ на тест индивидуально.
4. UI: логин → открыть программу (видна на главной по имени) → `pass_onboarding()` → вкладка
   «Курсы и тесты» → карточка теста (может не быть видна сразу — один reload+retry) → клик
   «Начать» → плеер открывается в новой вкладке (`/testing/player/{id}/{uuid}`), **загружается
   не мгновенно** (первые ~5-8с — только герб на пустом фоне, нужен явный wait, не
   `wait_until="load"` на переход, а пауза/ожидание селектора после).
5. Отвечать нужно в цикле на ОБА вопроса. Подводный камень: `.v-selection-control:has-text('Правильный
   ответ').first` **не всегда берёт нужный элемент** — `shuffle_answers=True` по умолчанию
   рандомизирует порядок вариантов, и `:has-text()` на этом классе иногда возвращает не тот
   элемент (однажды результат теста вышел 0% вместо ожидаемых ~50-100%). Надёжный способ —
   перебрать все `.v-selection-control` и сверить `inner_text()` каждого поэлементно, беря
   именно тот, где написано «Правильный ответ» (для вопроса-заглушки без такого текста — брать
   первый попавшийся, это не играет роли при `completion_percent=0`). После выбора — «Ответить»,
   затем «Следующий вопрос»/«Далее».
6. Экран результата («Успешное прохождение... Ваш результат: N%») — **отдельная кнопка
   «Завершить»**, которую обязательно нужно нажать (не «Повторить попытку»); без этого клика
   результат не фиксируется и сертификат не начисляется (ранний раунд без этого клика не
   дал ничего даже после 45с ожидания).
7. После клика «Завершить» — возврат на страницу программы. Через **~20 секунд** на
   `/portal-notifications` уже видно уведомление: «Сертификат — Поздравляем, Вы завершили
   обучение по программе «…». Вам доступен сертификат об успешном прохождении. Вы можете
   скачать сертификат в вашем профиле или по ссылке: `/certificate/{uuid}`». На
   `/profile/{user_id}` → вкладка «Мои сертификаты» — строка с названием программы и кнопкой
   «Скачать».

**Путь через курс Tincan (отвергнут)**: активити-сертификат (`template_type="activity"`) на
обычный тест/опрос бэкенд отклоняет 422 «Выбранное значение для content_ids.0 некорректно» —
этот тип сертификата привязывается только к Tincan-курсам. Повторный прогон уже существующего
черновика `scripts/_recon_cert_final.py` (курс Tincan + activity-сертификат + реальное
прохождение через вложенный плеер в iframe) подтвердил это тупиковым: прохождение упёрлось в
уже задокументированный дефект стенда — кнопка «Начать тест» внутри `#iframe` не появляется
(тот же блокер, что в `test_courses_table_progress.py` и обоих xfail-тестах курса Tincan).
Поэтому для автоматизации TC-E2E-039 используется именно поток + тест + `program_stream`-сертификат,
а не курс + `activity`-сертификат.

**Осталось нетронутым**: админская вкладка «Сертификаты» в карточке пользователя (упомянута в
`docs/e2e/offline_events_recon.md`) — не открывалась, не требовалось для подтверждения сценария.

## Отметка посещения в инд. треке (TC-E2E-037, открытый пункт) — разведано, маршрут не найден

Карточка пользователя в админке → «Назначения» → «Индивидуальная траектория обучения» →
подвкладка **«Очные»** — найдена (календарная сетка по дням недели/часам, не таблица, как у
ПЗ/курсов). Созданное через `POST /users/content/offline` занятие видно в сетке карточкой с
названием/местом/временем/преподавателем (подтверждено и вручную владельцем — создание через
UI карточки пользователя, занятие появляется у слушателя в «Индивидуальное обучение» →
«Расписание», `/education/personal/schedule?d={id}&e={id}`).

**Клик по карточке занятия в этой сетке ничего не открывает** — ни модалки, ни детальной
панели, ни в DOM (3 попытки: обычный клик, клик после `scroll_into_view_if_needed`, JS-скролл
+ force-клик). В отличие от потоковых schedule-items, здесь нет очевидного
«кликнуть → отметить присутствие».

**Гипотеза, не проверена живым сценарием**: отметка идёт через **QR-код слушателя**, не через
клик в этом списке. В профиле слушателя (`/profile/{id}`) есть блок «Мой QR-код... необходимый
для отметки (регистрации) на очных лекциях и мероприятиях» (увиден в разведке сертификата, см.
выше). У потокового варианта тоже есть отдельный QR-маршрут
(`GET /streams/{stream}/schedule-registration-link/{linkType}`, offline_events_recon.md) —
похоже, QR — общий механизм отметки для обоих треков, а не что-то специфичное для потока.
Чтобы закрыть этот пункт, нужно живьём пройти сценарий сканирования (или найти, что именно
дёргает сканер QR, по сети) — не сделано.
