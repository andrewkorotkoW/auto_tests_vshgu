# Отчёт: миссия «мобильная вёрстка портала + ручной чек-лист Android-оболочки» — итог

Миссия `docs/plans/2026-10-06_mobile_android_mission.md`. Это итоговый отчёт по всей миссии
(четвёртая, завершающая задача); предыдущая версия этого файла описывала только часть 1 (первый
зелёный тест) — ниже актуализировано по факту всех трёх предыдущих задач и собственного прогона.
Код в этой задаче не менялся — только отчёт.

## Часть 1 — мобильный профиль в auto_tests_vshgu (сделано, michael + dwight)

- `conftest.py`: единая сборка параметров контекста `_context_kwargs(request, storage_state=None)`
  вместо трёх копий viewport'а. Включение мобильного режима — опция `--mobile` или `MOBILE=1`
  (равнозначны, `_is_mobile_mode`), desktop-поведение без флага не изменилось. Константа
  `MOBILE_DEVICE` — Pixel 7 (viewport 412×839, `device_scale_factor` 2.625, `is_mobile`/`has_touch`,
  мобильный `user_agent`), видео-запись в мобильном режиме — под размер устройства и включена всегда
  (не только в test_hub), прикладывается в Allure для каждого теста, а не только при падении.
  Фикстуры `is_mobile` и `build_context_kwargs` — для мобильных веток в page objects и для чужих
  `conftest.py` (без self-import `import conftest`, см. `docs/mobile/layout_facts.md`/README §19).
- Маркер `mobile` в `pytest.ini`, зона `mobile` в `tests/product_map.yml`.
- `docs/mobile/layout_facts.md` — факты по 6 экранам (вход, список программ, активити, карточка
  программы, профиль, уведомления), снятые на develop в viewport Pixel 7; кандидаты в дефекты
  вёрстки зафиксированы там же (см. раздел ниже).
- Набор `tests/ui/mobile/` — 5 тестов, покрывают все 6 экранов плана (сертификат — внутри сценария
  карточки программы, но не доведён до конца, см. ниже): вход→список программ, активити (простой
  тест), карточка программы, профиль, уведомления. Allure: `allure.dynamic.parameter("device",
  "Pixel 7")` + финальный скриншот в каждом тесте.
- README §19 «Мобильная вёрстка» — описывает запуск (`MOBILE=1 HEADLESS=1 pytest -m mobile --env
  develop`) и как добавлять мобильные тесты.

## Часть 2 — ручной чек-лист Android-оболочки (сделано, pam)

`docs/test_cases/mobile/app_shell.md` — 10 ручных кейсов `TC-MOBILE-APP-001…010` (установка/первый
запуск и запрос уведомлений, вход через WebView, список программ, загрузка файла через камеру и
через галерею, кнопка «назад», поведение без сети/`offline.html`, возврат из фона, внешние ссылки,
push-уведомление). Чек-лист явно заблокирован до появления dev-сборки apk
(`portal-develop.d2.devspark.ru`) — прод не используется ни одним кейсом. `*.apk` добавлен в
`.gitignore`, путь к apk передаётся через `MOBILE_APK`.

**Импорт этого чек-листа в test_hub — ручная операция владельца, не автоматическая.** В отличие от
автотестов (которые попадают в test_hub через обычный прогон/test_hub_plugin), кейсы
`app_shell.md` не синхронизируются скриптами автоматически сами по себе до явного запуска владельцем.

### Важное расхождение с перепиской/README на момент этой задачи

Задание прямо предупреждало не доверять слепо числам из переписки задачи t2 — они действительно
устарели, и не только в переписке: **README §19 (строка про набор `tests/ui/mobile/`) на момент
этой задачи ещё называет `test_mobile_profile_and_certificates.py` тестом с `xfail`**, хотя в
коммите `ffe2105` (07.10, до коммита `725124f`, которым правилось само README §19) `xfail` с этого
теста уже снят — кандидат «зависающий спиннер `.v-progress-circular`» на вкладке «Профиль» не
подтвердился при перепроверке и был опровержен (ошибка была в самом тесте: клик по нижней панели
сразу после загрузки — no-op, и ожидание email, которого на вкладке нет). Открыл сам тест
(`tests/ui/mobile/test_mobile_profile_and_certificates.py`) — `@pytest.mark.xfail` в коде
действительно отсутствует, и мой прогон подтверждает: тест зелёный, не xfailed/xpassed. Это
несоответствие в README — факт для следующей задачи по документации, в этом отчёте код/README не
менялись (задание ограничивало правки только этим файлом отчёта).

## Полный список xfail

**На момент этого отчёта в наборе `tests/ui/mobile/` xfail нет** — единственный ранее существовавший
(`test_mobile_profile_and_certificates.py`, см. выше) снят после опровержения причины. Это
подтверждено и текстом самого `docs/mobile/layout_facts.md` (п. 5: «Перепроверка 07.10 (develop):
„бесконечного спиннера“ нет»), и моим прогоном (0 xfailed из 5).

Открытые кандидаты в дефекты мобильной вёрстки — зафиксированы в `docs/mobile/layout_facts.md`, но
**не покрыты активным xfail-тестом** (либо не являются дефектом вёрстки по сути, либо сценарий не
дописан до проверки):

1. **Заголовок теста обрезается без переноса/троеточия** на узком экране активити (`/testing/player`,
   п. 3 `layout_facts.md`) — на desktop заголовок переносится, на Pixel 7 carточка теста уже́
   названия. Визуальный дефект, кандидат для отдельного xfail/тикета, автотестом как xfail не
   закреплён.
2. **Сертификат после прохождения активити не проверен до конца** (п. 4 `layout_facts.md`) —
   блокер — `CertificatesEndpoint.assign_template(content_type="activity", content_ids=[...])`
   отдаёт `422` (API ждёт другой тип content_id, видимо потока/стрима). Это дефект/особенность API
   сертификатов, не мобильной вёрстки — зафиксирован как открытый вопрос, не xfail мобильного теста.
3. **Белый экран вместо `assets/offline.html` при ошибке SSL** на старых Android (замечание из
   раздела «Факты про приложение» плана, воспроизведено на эмуляторе Android 8) — это дефект
   Android-оболочки (WebView/TrustManager), не веб-вёрстки Playwright-тестов; относится к зоне
   ручного чек-листа части 2 (`TC-MOBILE-APP-007`), а не к набору `tests/ui/mobile/`.
4. *(Снят, не открытый дефект)* спиннер на вкладке «Профиль» — см. раздел выше, перепроверка 07.10
   не подтвердила зависание; оставлено здесь только для прослеживаемости истории кандидата.

Факт про авто-вопрос-заглушку в тестах (`POST /tests` сам добавляет вопрос «Заголовок вопроса…»,
`layout_facts.md` п. 3, дополнение) — это не дефект вёрстки, а свойство данных API; устранено
ожиданием видимого вопроса вместо ожидания конкретного текста, в текущем прогоне не вызывает ни
xfail, ни failed.
