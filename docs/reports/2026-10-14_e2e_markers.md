Обновлены все упоминания путей:

## 2. Часть 2 — маркер `e2e` на сквозные сценарии слушателя

замыкание статистикой, добавлены по подтверждению владельца вечером 14.10): онбординг, курс и

таблица «Часть 2» плана миссии. Существующий маркер `lrs`/`smoke`/`develop`/`xfail` у этих тестов
не трогали.

Уже были помечены маркером `e2e` до этой миссии: `tests/ui/lrs/test_lrs_report.py` (один тест) и

## 3. Проверка `pytest --collect-only`

Обе команды выполнены локально в этом worktree (только сбор, без прогона):

```
$ pytest --collect-only -q -m e2e
...
=============== 21/686 tests collected (665 deselected) in 3.51s ===============
```

```
$ pytest --collect-only -q tests/stage_lpd
...
========================= 15 tests collected in 0.14s ==========================
```

**21 тест** под маркером `e2e` = 19 тестов из `tests/ui/*` (18 файлов, один даёт два теста —
`tests/ui/courses/tincan/individual/test_user_tincan_individual_flow.py`) + 2 LRS-теста. **15
тестов** в `tests/stage_lpd` — совпадает с числом, что раньше было в `tests/e2e/{api,ui}` (7
файлов `api/`, 8 файлов `ui/`), перенос не потерял и не задвоил тесты.

Расхождение с планом миссии: в плане (Часть 2, строка «Проверка») итоговое число после основной
части мерджа названо «21 тест» уже с учётом пунктов 17–18 (тикет, статистика) — фактический
прогон подтверждает именно 21, а не промежуточные 19 из более ранней версии той же таблицы.

## 4. Часть 3 — кейсы `docs/test_cases/e2e.md`

Кейсы ЛПД (бывшие TC-E2E-004…018) перенесены в новый `docs/test_cases/stage_lpd.md` с заменой
пути автотеста на `tests/stage_lpd/…`, номера сохранены ради импорта в test_hub. В `e2e.md`
остались API-цепочки TC-E2E-001…003 и добавлены новые ручные кейсы:

- **TC-E2E-019…035** (17 кейсов) — по одному на тест из таблицы Части 2 (один файл,
  `test_user_tincan_individual_flow.py`, даёт два кейса — TC-E2E-030/031); шаги и ожидаемые
  результаты переписаны из `allure.step` самих тестов. Два LRS-теста с маркером `e2e` не
  дублируются — у них уже есть TC-LRS-011/013 в `docs/test_cases/lrs.md`.
- **TC-E2E-036…040** — черновики без автотеста (очное мероприятие в потоке, очное мероприятие в
  индивидуальном треке, опрос в потоке + неавторизованная попытка, сертификат слушателя
  программы, достижение за материал БЗ), ждут разведки владельца на k8s.

### Найденный пробел

Кейсы TC-E2E-019…035 покрывают 17 из 19 тестов `tests/ui/*` с маркером `e2e` — **два теста,
добавленные дополнением владельца «17–18» (техподдержка `test_user_creates_ticket_and_sees_it` и
замыкание статистикой `test_status_passed_updates_after_change_state`), в `docs/test_cases/e2e.md`
кейса не получили.** В тексте файла (служебный комментарий, строки 17–28) это явно не отражено —
там говорится про «16 файлов / 17 тестов + 2 LRS = 19», что было верно до добавления пунктов
17–18 в Часть 2, но не обновлено при написании кейсов. Итог: задокументировано 19 из 21
e2e-теста, два — без кейса. Фикс не в рамках этой (документационной) миссии — следующему, кто
будет писать кейсы по `docs/test_cases/e2e.md`, нужно добавить TC-E2E-041/042 по этим двум
тестам (nodeid'ы есть в выводе collect-only выше, в README разделе 21 и в таблице Части 2 плана).
