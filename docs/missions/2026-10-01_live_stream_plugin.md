# Миссия: плагин test_hub — живая трансляция браузера (screencast) и видео теста

Записано 01.10.2026. Парная миссия к `test_hub/docs/missions/2026-10-01_live_stream.md` —
**контракт эндпоинтов и форматов взят оттуда, читать первым делом.** Плагин `utils/test_hub_plugin.py`
уже шлёт разметку `[TH]`, шаги и кадры по шагам; сюда добавляются два канала.

## 1. Живая трансляция (screencast через CDP)

- При `pytest_runtest_logstart` UI-теста (у теста есть активная страница Playwright — тот же
  поиск, что в `_find_active_page`) открыть CDP-сессию: `page.context.new_cdp_session(page)`,
  `Page.startScreencast` с `format=jpeg`, `quality=50`, `maxWidth=960`, `maxHeight=600`,
  `everyNthFrame=2`. На событие `Page.screencastFrame` — сразу `Page.screencastFrameAck`
  (иначе поток встанет), кадр (base64 → bytes) положить в очередь «последний кадр».
- Отправка — фоновый поток (`threading.Thread(daemon=True)`), не чаще `TH_LIVE_FPS` (по
  умолчанию 3) кадров в секунду: берёт последний кадр из очереди, `POST {TH_URL}/api/runs/{TH_RUN_ID}/live`
  (multipart `nodeid`, `ts`, `step` = имя текущего шага из `_on_step_start`, `file` jpeg),
  таймаут 2 с, ошибки сети глотать и считать; после 20 ошибок подряд — выключить трансляцию
  для этого теста и написать одну строку в лог. Тест из-за трансляции падать не должен никогда.
- При завершении теста — `Page.stopScreencast`, `detach` сессии, поток останавливается.
  Если страница закрылась раньше (тест сам закрыл контекст) — тихо завершить.
- Страница может смениться внутри теста (новый контекст для гостя, попап): при `_on_step_start`
  перепроверять активную страницу и переподключать screencast, если она другая.
- Выключатель `TH_LIVE=0` (env) — трансляция не запускается; без `TH_URL` плагин, как и раньше,
  выключен целиком.
- Sync-API Playwright: события доставляются, пока главный поток внутри вызовов Playwright, —
  для тестов это норма; проверить на локальной мок-странице (`file://` html с таймером), что
  кадры действительно идут во время `page.wait_for_timeout`.

## 2. Видео теста

- Запись — средствами Playwright: в фикстурах контекста `conftest.py` (`page`, `user_page`,
  `admin_page` и все `new_context(...)` внутри фикстур) добавить `record_video_dir` и
  `record_video_size={"width":1280,"height":720}`, **только когда** плагин включён или задан
  `TH_VIDEO=1`; каталог — `workspace/video/<run_id>/` в корне проекта (в `.gitignore`).
  Локальные прогоны без test_hub не меняются.
- После завершения теста (`pytest_runtest_logreport`, фаза `call`/`teardown` последнего
  контекста) путь видео известен только после `context.close()`: закрыть контекст в фикстуре,
  взять `page.video.path()`, отправить `POST /api/runs/{id}/tests/{nodeid}/video` (webm,
  `duration_ms`) в фоновом потоке, файл удалить после успешной отправки; при ошибке — оставить
  файл и написать в лог. Тесты с несколькими контекстами — отправлять видео основного
  (`page`/`user_page`), остальные удалять.
- Видео дополнительно прикладывать в allure (`allure.attach.file(..., attachment_type=WEBM)`)
  только для упавших тестов — чтобы Allure-отчёт не раздувался.

## 3. Проверки

- Unit-тесты плагина без стенда (как существующие `tests/tools/test_test_hub_plugin.py`):
  троттлинг отправки, отключение после серии ошибок, `TH_LIVE=0`, отправка видео на мок-сервер,
  удаление файла после успеха, ничего не делается без `TH_URL`.
- Один локальный UI-тест на мок-странице `file://` (html в `tests/tools/fixtures/`) с
  запущенным мок-сервером (http.server в фикстуре): приходят ≥ 3 live-кадра за 2 секунды и одно
  видео. Стенды не трогать.
- README и `docs/QA_GUIDE.md`: «Плагин test_hub» — эфир, видео, переменные `TH_LIVE`,
  `TH_LIVE_FPS`, `TH_VIDEO`. `.env.example` дополнить.
