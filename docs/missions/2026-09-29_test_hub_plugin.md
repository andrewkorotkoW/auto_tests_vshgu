# Миссия: плагин test_hub в проекте автотестов — кадры по шагам и разметка вывода по тестам

Записано 29.09.2026. Парная миссия к `test_hub/docs/missions/2026-09-29_run_window_stage2.md`
(окно прогона «Сплит») и `2026-09-29_testcases_stage2.md` (скриншоты в тест-кейсах).

## Что должно получиться

1. **Плагин `utils/test_hub_plugin.py`**, подключается в `conftest.py` через `pytest_plugins`
   или хуками. Работает только когда раннер test_hub передал env `TH_URL`, `TH_RUN_ID`,
   `TH_RUN_TOKEN`; без них — тихо выключен, локальные прогоны не меняются.
2. **Разметка вывода**: хуки `pytest_runtest_logstart`/`pytest_runtest_logreport` печатают в
   stdout строки `[TH] start <nodeid>` и `[TH] end <nodeid> <passed|failed|skipped|xfailed>`
   (flush сразу, чтобы раннер видел их в потоке).
3. **Шаги**: обёртка над `allure.step` — при входе в шаг печатать `[TH] step <nodeid> <n> <имя>`.
   Сделать это без правки всех тестов: патч `allure.step` в плагине (контекст-менеджер и
   декоратор), либо хук allure `pytest_allure_step_start`, если он есть в установленной версии.
4. **Кадры UI-тестов**: если у теста есть активная страница Playwright (фикстура `page`,
   `user_page`, `admin_page` и т.п. — найти по `request.node.funcargs`), на каждом шаге делать
   `page.screenshot()` (уменьшенный, ширина ≤ 1280, PNG) и (а) прикладывать в allure
   `allure.attach(..., name=f"step {n}", type=PNG)` — это же становится источником скриншотов
   в тест-кейсах test_hub; (б) отправлять `POST {TH_URL}/api/runs/{TH_RUN_ID}/frames`
   (multipart: nodeid, step, file; заголовок `Authorization: Bearer {TH_RUN_TOKEN}`) в фоне
   с таймаутом 3 с и без падения теста при ошибке сети. Лимит кадров на тест (например 40),
   дальше кадры пропускаются.
5. **API-тесты**: кадров нет; строки логов запросов (`client.py` уже пишет `POST …`,
   `Response [200]`) остаются как есть — раннер свяжет их с тестом по `[TH] start/end`.
6. Плагин покрыть unit-тестами без стенда: разметка строк, выключенное состояние без env,
   отправка кадра в мок-сервер, лимит кадров.

## Ограничения

- Стенды не трогать, прогоны на develop/stage не запускать; проверка — `pytest` по своим
  unit-тестам плагина и одним-двумя локальными тестами с мок-страницей, если возможно.
- Не менять существующие тесты и page objects, кроме `conftest.py` (подключение плагина).
- Коммиты небольшие, на русском; README: раздел «Плагин test_hub».
