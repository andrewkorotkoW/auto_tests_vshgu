# Разведка helpdesk-develop (05.10.2026)

Снято Playwright под той же сессией/учёткой, что `admin_page` в `conftest.py`
(`config.environments.get_storage_state_path(ENVIRONMENTS["develop"], role="admin")`,
`HEADLESS=1`). Кука сессии (`develop`) привязана к домену `.d2.devspark.ru` — работает сразу
на `helpdesk-develop.d2.devspark.ru` без отдельного логина. Чистая разведка: ничего не
создавалось/не удалялось/не сохранялось, только GET-навигация + наблюдение за XHR; формы
открывались, но не сабмитились (кроме набора текста в полях живого поиска — это GET-подобный
побочный эффект без мутаций).

## 1. Общая архитектура (неожиданность относительно плана миссии)

У хелпдеска **нет отдельного REST API с префиксом `/api/...`** — это сервер-рендерящаяся
Laravel-админка (judging by `UserCrudController.php`, атрибуты `bp-button`, `data-tbx-*`).
Схема одинакова для всех разделов:

- Список раздела — обычный `GET /admin/<entity>` (полный HTML, таблица на jQuery DataTables).
- Подгрузка строк таблицы — `POST /admin/<entity>/search`, `Content-Type:
  application/x-www-form-urlencoded`, тело — стандартные DataTables-параметры
  (`draw`, `columns[i][data|name|searchable|orderable|search[value]]`, глобальный `search[value]`
  для живого поиска, `start`/`length` для пагинации). Ответ — `application/json`:
  `{"draw":N,"recordsTotal":N,"recordsFiltered":N,"data":[[...готовый HTML ячеек...]]}`
  (ячейки — уже отрендеренный HTML, не чистые данные).
- CRUD-страницы — `GET /admin/<entity>/create`, `GET /admin/<entity>/{id}/edit`,
  `GET /admin/<entity>/{id}/show`, сабмит форм — `POST`/`PUT` на тот же базовый URL со скрытыми
  полями `_token` (CSRF), `_method`, `_http_referrer`, `_form_id`, `_save_action`.
- Удаление — `<a onclick="deleteEntry(this)" data-route="/admin/<entity>/{id}">` → модальное
  подтверждение → DELETE на `data-route`.
- CSRF: `<meta name="csrf-token" content="...">` в `<head>` + JS на каждый AJAX подставляет
  заголовок `X-CSRF-TOKEN`; AJAX также шлёт `X-Requested-With: XMLHttpRequest`,
  `Accept: application/json, text/javascript, */*; q=0.01`. Авторизация — той же сессионной
  кукой `develop` (`.d2.devspark.ru`), без отдельного Bearer/JWT для хелпдеска.
- Дашборды — отдельный паттерн: `POST /admin/dashboard/data/<metric>` на каждый график
  (`ticketCount`, `ticketClosedCount`, `ticketClosedAverageMessageCount`,
  `ticketClosedByTimerCount`, `ticketCountByRequestSource`, `ticketCountByRequestType`,
  `ticketCategories`, `ticketSubcategories`, `ticketStatuses`, `ticketCountByTemplates`,
  `ticketCountByApplicantType`), ответ — готовый конфиг Highcharts
  (`{"title":...,"xAxis":{"categories":[...]},"series":[{"name":...,"data":[...]}],"chart":{"type":"line"}}`).
- Назначение роли — отдельный суб-паттерн: кнопка в списке пользователей открывает
  **iframe-модалку** (`data-tbx-component="CommonIframeModalButton"`) на
  `GET /admin/user/{id}/assign-role` — отдельная мини-страница с чекбоксами ролей и формой
  `POST` на тот же URL (скрытые поля `roles[admin]`, `roles[support]`, `roles[group_admin]`).

## 5. Находки / кандидаты в дефекты

1. **HTTP 500 при поиске пользователя по многословной строке.** `POST
   /admin/user/search` с `search[value]`, содержащим пробел (например
   `"Фокина Victpor"`), возвращает `500 Internal Server Error`:
   `{"message":"Undefined array key \"data\"","exception":"ErrorException","file":
   "/srv/app/app/Http/Controllers/Admin/UserCrudController.php","line":82}`. Воспроизводится
   стабильно (10+ повторов). Однословный поиск по ФИО не вызывает ошибку, но и не фильтрует.
   Кандидат в баг-репорт для Части 3 (можно оформить как `xfail`/отдельный баг-тест).
2. Поиск по ФИО (и в «Пользователи», и в «Заявители») не работает как живой посимвольный —
   нужно ≥2 полных слова. Между собой ведут себя по-разному: заявители просто не находят (0
   результатов), пользователи — либо не находят, либо падают в 500 (в зависимости от
   количества слов/пробелов). Нужно уточнить при оформлении автотестов, фиксировать как
   известное ограничение, не «ошибку assert».
3. Пароль IMAP при создании/редактировании группы вводится в `type="text"`, а не
   `type="password"` — значение видно в поле открытым текстом. Минорная UX/security заметка,
   не блокер разведки.
4. Заголовок страницы `<title>` не всегда обновляется при прямой навигации (например,
   `/admin/user/{id}/show` отдаёт `<title>Дашборды</title>` при корректном содержимом
   страницы) — не влияет на функциональность, но если автотест будет проверять `page.title()`,
   это даст false negative; проверять `h1`/видимый контент, не `<title>`.
5. Название пункта меню «Типы результата» не совпадает с заголовком открываемой страницы
   («Результаты обработки» / h1 «Результаты Обработки») — косметическое несоответствие.

## 6. Ограничения этой разведки

- Клики на иконки удаления (группа/шаблон) и на шестерёнку назначения ролей из списка
  пользователей через Playwright в headless-режиме стабильно возвращали один и тот же общий
  текст подтверждающей модалки про «тег» («Вы уверены что хотите удалить? Тег останется в
  общем списке тегов…») — похоже, селектор ловил не ту (общую/скрытую) модалку, использованную
  в разметке лэйаута для другого действия (удаление тега с тикета), а не настоящую
  модалку конкретного действия. Точный текст подтверждения удаления группы/шаблона и
  визуальный вид модалки назначения ролей **не подтверждены достоверно** — при написании UI
  автотестов эти тексты не хардкодить, проверять по факту появления модалки/кнопок
  «Отмена»/«Удалить»/«Сохранить», а не по конкретной строке.
- Формы не сабмитились (создание/редактирование/удаление реальных данных запрещено
  правилами миссии) — обязательность полей (`required`) не проверена напрямую, только по
  описанию из v.2 и визуальной разметке (звёздочки/подписи не всегда видны в DOM-дампе).
  Перепроверить на этапе автоматизации через `expect_status` на `422` при пустых полях.
- Фильтры дашборда (поля `group_id[]`/`user_id[]`/`status[]`/`request_source[]`/`tags[]`/
  `direction[]`) собраны по DOM без открытия модалки кликом (чтобы не плодить лишние сетевые
  запросы на уже отрисованные графики) — состав полей может быть неполным/с другими подписями,
  не раскрытыми в разметке; перепроверить визуально.
- Разведка велась под пользователем-администратором с ролью «Администратор» (глобальная) —
  поведение для ролей «Администратор организации» / «Поддержка» / «Поддержка (Helpdesk)» не
  проверялось (может отличаться состав видимых разделов/кнопок).
